6.1.6.5. OpenFAST 디버깅 중

Fortran 프로젝트이기 때문에 OpenFAST는 디버깅하기 어려울 수 있으며 프로세스는 각 시스템 및 환경마다 고유합니다. 일부 OpenFAST 사례는 메모리 공간이 상당히 클 수 있으며 코드에서 관심 지점에 도달하는 데 오랜 시간이 걸릴 수 있다는 점을 명심하세요. 테스트 사례를 신중하게 선택하면 상당한 시간을 절약할 수 있습니다.

OpenFAST에 들어가기 전에 모든 디버깅 도구가 올바르게 설정되었는지 확인하기 위해 작은 포트란 프로그램을 작성하는 것이 도움이 될 수 있습니다. 할당되지 않은 배열 요소에 액세스하는 등의 작업을 수행하여 버그를 시뮬레이션하고 주어진 도구 세트를 사용하여 버그를 잡을 수 있는지 확인하십시오.

참고

모든 시스템의 요구 사항은 OpenFAST를 다음과 같이 컴파일하는 것입니다. 디버그 방법.

6.1.6.5.1. Windows에서 디버깅

Intel 도구를 사용하는 Windows 개발자는 디버깅을 위해 OpenFAST 리포지토리에 포함된 Visual Studio 솔루션을 사용할 수 있습니다. 이는 인텔의 많은 지원을 받는 간단한 프로세스입니다.

그렇지 않은 경우 Unix 스타일 환경에서 컴파일하는 Windows 개발자는 다음 단계를 진행해야 합니다. Linux 및 macOS에서 디버깅.

6.1.6.5.2. Linux 및 macOS에서 디버깅

먼저 다음 설정을 통해 디버그 모드에서 OpenFAST를 컴파일합니다. CMAKE_BUILD_TYPE "디버그"로. 이 작업은 명령줄에서 다음을 사용하여 수행할 수 있습니다.

cmake .. -D CMAKE_BUILD_TYPE=Debug

또는 사용하여 ccmake 명령줄 cmake gui를 열어 변경합니다.

GNU 디버거, gdb, 컴파일된 코드를 디버깅하는 데 적합합니다. 개발자가 중단점을 추가하고 변수를 검사할 수 있는 포괄적인 명령줄 인터페이스가 있습니다.

IDE를 통해 디버거를 구동하면 코드를 훨씬 더 효율적으로 검사할 수 있습니다. 잘 작동하는 것으로 알려진 IDE 중 하나는 다음과 같습니다. 비주얼 스튜디오 코드 와 함께 네이티브 디버그 확대. 당신은 설정할 수 있습니다 실행 구성 IDE를 통해 특정 OpenFAST 사례를 디버깅할 수 있습니다. 이렇게 하려면 시작 구성을 열고 다음과 유사한 블록을 추가하세요.

{
    "name": "AOC_WSt",
    "type": "gdb",
    "request": "launch",
    "printCalls": false,
    "showDevDebugOutput": false,
    "valuesFormatting": "prettyPrinters",
    "gdbpath": "gdb",
    "target": "${workspaceRoot}/build/glue-codes/openfast/openfast",
    "cwd": "${workspaceRoot}/build/reg_tests/glue-codes/openfast/AOC_WSt/",
    "arguments": "${workspaceRoot}/build/reg_tests/glue-codes/openfast/AOC_WSt/AOC_WSt.fst",
}

6.1.6.5.2.1. macOS 관련 구성

macOS의 GDB는 시스템이 프로세스를 인계받기 전에 몇 가지 구성이 필요합니다. 권장되는 사항은 다음과 같습니다. gdb 홈브류와 함께 설치

brew info gdb
brew install gdb

완료 후에는 반드시 주의사항을 따라 설치를 완료해 주세요. 을 위한 gdb 8.2.1, 다음과 같습니다.

==> Caveats
gdb requires special privileges to access Mach ports.
You will need to codesign the binary. For instructions, see:

https://sourceware.org/gdb/wiki/BuildingOnDarwin

On 10.12 (Sierra) or later with SIP, you need to run this:

echo "set startup-with-shell off" >> ~/.gdbinit

macOS의 네이티브 디버그의 경우 다음 줄을 추가하여 포트란 파일에 중단점을 허용하도록 확장을 해킹해야 합니다. .vscode/settings.json:

{
    "debug.allowBreakpointsEverywhere": true
}
