4.2.5. 선형화

OpenFAST는 주기적(또는 정적) 작동점에 대해 전체 다중 물리 시스템을 선형화하여 다음 형식의 연속시간 1차 상태공간 행렬을 생성할 수 있습니다.

\[\begin{split}\dot{\mathbf{x}} &= A\,\mathbf{x} + B\,\mathbf{u} \\ \mathbf{y} &= C\,\mathbf{x} + D\,\mathbf{u}\end{split}\]

다음 연성 행렬과 함께 dUdu (입력-입력 피드스루) 및 dUdy (출력-입력 커플 링). 선형화 엔진은 다음 위치에 있습니다. modules/openfast-library/src/FAST_ModGlue.f90.

  • 선형화를 위한 사용자 입력

  • 선형화를 위한 모듈 지원

  • 변수 선택

  • 정상 상태 트리밍(CalcSteady)

  • 동작점에서의 선형화

  • 출력 파일 형식

  • 변수 명명 규칙

  • 모듈 개발자의 책임

4.2.5.1. 선형화를 위한 사용자 입력

다음 매개변수는 기본 OpenFAST 입력 파일(*.fst) 아래 선형화 부분.

매개변수

유형

설명

Linearize

논리형

마스터 스위치. 다음으로 설정 True 모든 선형화 기능을 활성화합니다. 언제 False 다른 모든 선형화 매개변수는 무시됩니다.

CalcSteady

논리형

다음의 경우 True, OpenFAST는 먼저 각 목표 방위각의 출력이 하나의 로터 회전에서 다음 회전으로 수렴할 때까지(정상 상태 트리밍) 시뮬레이션을 실행한 다음 각 방위각에서 선형화를 수행합니다. 언제 False, 선형화는 사용자가 지정한 절대 시뮬레이션 시간(LinTimes).

TrimCase

정수

컨트롤러 자유도가 조정되는 동안 조정됨 CalcSteady 주기적인 정상상태를 달성하는 것입니다.

  • 1 – 요

  • 2 – 발전기 토크

  • 3 – 집단 블레이드 피치

TrimTol

실수

RMS 로터 1회전에 걸쳐 정규화된 출력 오류에 대한 수렴 허용 오차입니다. 오류가 이 값 아래로 떨어지면 트리밍이 중지됩니다. 일반적인 값: 1.0e-5.

TrimGain

실수

내장 트림 컨트롤러에서 사용되는 비례 게인입니다. 단위는 요/피치의 경우 rad/(rad/s)이고 토크의 경우 N·m/(rad/s)입니다.

Twr_Kdmp

실수

인공 타워 감쇠 계수(N/(m/s))가 추가되었습니다. CalcSteady 과도 현상을 완화하고 안정된 상태에 더 빨리 도달하도록 실행합니다. 비활성화하려면 0으로 설정합니다.

Bld_Kdmp

실수

동안 인공 블레이드 감쇠 계수(N/(m/s)) CalcSteady.

NLinTimes

정수

로터 회전당 선형화 시점 수(또는 동일한 간격의 절대 시점 수) CalcSteady=False). ≥ 1이어야 합니다. 주기 모델의 경우 회전당 변동을 해결하려면 일반적으로 최소 12개의 방위각이 필요합니다.

LinTimes

실수 배열

선형화할 절대 시뮬레이션 시간(초) CalcSteady=False. 길이는 동일해야 합니다. NLinTimes. 무시되는 경우 CalcSteady=True.

LinInputs

정수

어떤 입력 변수가 표시되는지 제어합니다. B 및 D 행렬.

  • 0 (LIN_NONE) – 입력이 없습니다. 상태 행렬만 생성합니다.

  • 1 (LIN_STANDARD) – 플래그가 지정된 입력 VF_Linearize 모듈별(기본값은 각 모듈의 InitVars).

  • 2 (LIN_ALL) – 디버그 입력을 포함한 모든 모듈 입력.

LinOutputs

정수

표시되는 출력 변수를 제어합니다. C 및 D 행렬.

  • 0 (LIN_NONE) – 출력이 없습니다.

  • 1 (LIN_STANDARD) – WriteOutput 채널만(VF_WriteOut 깃발).

  • 2 (LIN_ALL) – 모든 모듈 출력.

LinOutJac

논리형

다음의 경우 True (요구 LinInputs=LinOutputs=2), 디버깅을 위해 전체 모듈 야코비 행렬이 선형화 출력 파일에 기록됩니다.

LinOutMod

논리형

다음의 경우 True, 모듈별 .lin 파일은 전체 시스템 파일에 추가로 기록됩니다.

4.2.5.2. 선형화를 위한 모듈 지원

선형화 변수 순서에 나타나는 모듈(에서 설정) ModGlue_Init) 이다:

InflowWind → SeaState → ServoDyn → ElastoDyn → BeamDyn → AeroDyn → HydroDyn → SubDyn → MAP++ → MoorDyn

이 순서 목록에 없는 모듈은 다음과 같은 경우 치명적인 오류를 발생시킵니다. Linearize=True.

4.2.5.3. 변수 선택

동안 ModGlue_Init, VF_Linearize 플래그는 다음에 따라 변수에 적용됩니다. LinInputs 및 LinOutputs 설정:

  • 상태(x): VF_Linearize 플래그는 모든 참여 모듈의 모든 연속 상태 변수에 항상 설정됩니다.

  • 입력(u):

    • LIN_NONE → 모든 입력 변수에서 플래그가 지워집니다.

    • LIN_STANDARD → 뭐든지 지킨다 VF_Linearize 플래그가 모듈에 설정되었습니다. InitVars; 모듈 개발자는 기준 입력 세트.

    • LIN_ALL → 모든 입력 변수에 플래그가 설정됩니다.

    • 변수 VF_NoLin 항상 가지고있다 VF_Linearize 위 설정과 상관없이 지워집니다.

  • 출력(y):

    • LIN_NONE → 모든 출력 변수에서 플래그가 지워집니다.

    • LIN_STANDARD → 플래그는 다음을 전달하는 출력에만 설정됩니다. VF_WriteOut.

    • LIN_ALL → 모든 출력 변수에 플래그가 설정됩니다.

    • 변수 VF_NoLin 항상 제외됩니다.

결합된 변수 세트는 ModGlueType 명명된 Lin ~을 통해 ModGlue_CombineModules.

4.2.5.4. 정상 상태 트리밍(CalcSteady)

다음의 경우 CalcSteady=True, ModGlue_CalcSteady 주기성을 감지하기 위해 각 시간 단계에서 호출됩니다.

  1. 모듈 출력 태그가 지정되었습니다. VF_Linearize (을 제외한 VF_WriteOut)은 방위각으로 색인된 버퍼에 수집됩니다.

  2. 각각의 완전한 회전 후에 각 출력의 출력은 NLinTimes 방위각 목표는 정규화된 RMS 오류를 통해 이전 회전과 비교됩니다.

    \[\varepsilon = \sqrt{\frac{1}{N} \sum_{i=1}^{N} \left(\frac{y_i^{\rm current} - y_i^{\rm previous}}{r_i}\right)^2}\]

    여기서 \(r_i = \max(y_{i,\rm max} - y_{i,\rm min},\, 0.01)\) 는 현재 회전의 출력 범위입니다(거의 0으로 나누는 것을 방지하기 위한 바닥 포함).

  3. 다음의 경우 \(\varepsilon < \texttt{TrimTol}\), FoundSteady=True 그리고 선형화 전혀 NLinTimes 방위각은 자동으로 진행됩니다.

  4. 시뮬레이션이 약 2회전 이내에 도달하면 TMax 수렴하지 않으면 경고가 발생하고 선형화가 강제됩니다.

버퍼 샘플 사이의 방위각 보간은 다음의 외삽 루틴을 사용합니다. MV_ExtrapInterp (사용 가능한 샘플 수에 따라 상수, 선형 및 2차 방식 지원)

4.2.5.5. 동작점에서의 선형화

ModGlue_Linearize_OP 단일 작동 지점(시간/방위각)에서 전체 시스템 행렬을 조립합니다.

  1. 모듈 야코비안: 각 모듈에 대해 FAST_JacobianPInput 및 FAST_JacobianPContState 모듈별 하위 행렬을 계산하기 위해 호출됩니다. dYdu, dXdu, dYdx, dXdx 중심차 유한 미분에 의한 것입니다. 섭동 크기는 각 변수의 Perturb 필드(참조 모듈 변수(ModVar)).

  2. 작동점 추출: FAST_GetOP 현재 상태, 입력 및 출력을 선형화 배열(ModGlue%Lin%x, %u, %y).

  3. 커플링 매트릭스: 입력-출력 결합 행렬 dUdu 및 dUdy 일부 모듈 입력이 다른 모듈 출력의 함수라는 사실을 설명하기 위해 메시 매핑 야코비 행렬로 조립됩니다.

  4. 전체 시스템 조립: 모듈별 하위 행렬은 다음을 사용하여 결합된 글루 수준 행렬에 배치됩니다. iGlu 각각에 저장된 인덱스 범위 ModVarType.

  5. 산출: ModGlue_CalcWriteLinearMatrices 를 쓴다 .lin 다음을 포함하는 파일:

    • 작동점 값(x_op, u_op, y_op)

    • 선형화 채널 이름( LinNames)

    • 파생 순서 표시기(VF_DerivOrder1, VF_DerivOrder2)

    • 회전 프레임 플래그(VF_RotFrame)

    • 전체 시스템 매트릭스 A, B, C, D, dUdu, dUdy

    • 모듈별 행렬(만약 LinOutMod=True)

    • 완전 야코비안(만약 LinOutJac=True)

4.2.5.6. 출력 파일 형식

각 선형화 호출은 다음과 같은 파일을 생성합니다. <RootName>.<N>.lin 여기서 N 선형화 지수(1… NLinTimes). 파일은 일반 텍스트 ASCII 파일로 읽을 수 있습니다. openfast_io Python 라이브러리 또는 pyFAST 후처리 도구.

파일 헤더의 주요 필드:

  • Rotor_Speed – 선형화 시 회전자 속도(RPM)

  • Azimuth – 선형화 시간의 블레이드-1 방위각(deg)

4.2.5.7. 변수 명명 규칙

선형화 출력 파일에서 각 채널 레이블은 다음 패턴을 따릅니다.

<ModAbbr> <MeshName> <Field> [, component [, node [, unit]]]

예:

  • ED BlPitch1, rad – ElastoDyn 개별 블레이드-1 피치 상태

  • AD B1N001Fx force, node 1, N – AeroDyn 블레이드 1 노드 1 X-force 입력

  • BD_1 B1TipTDxr translation displacement, node 10, m – BeamDyn 인스턴스 1

모듈 개발자는 다음을 보장해야 합니다. Name 주장 MV_AddVar / MV_AddMeshVar 그리고 LinNames 후처리 도구와의 일관성을 위해 이 규칙을 따르세요.

4.2.5.8. 모듈 개발자의 책임

선형화에 참여하려면 모듈은 다음을 수행해야 합니다.

  1. 부르다 MV_AddVar / MV_AddMeshVar 적절한 VF_Linearize 깃발과 공급 LinNames 표준 선형화 세트에 나타날 수 있는 모든 변수에 대해.

  2. 구현하다 <Mod>_JacobianPInput 및 <Mod>_JacobianPContState 서브루틴(또는 레지스트리를 통해 분석적 야코비 행렬 제공) 글루 코드는 다음을 통해 이를 호출합니다. FAST_JacobianPInput / FAST_JacobianPContState 래퍼 FAST_Funcs.f90.

  3. 구현하다 <Mod>_GetOP (레지스트리를 통해) 상태, 입력 및 출력의 작동점 값을 추출합니다.

  4. 표시해야 하는 변수 ~ 아니다 선형화에 참여 VF_NoLin.

  5. 회전 참조 프레임의 변수를 다음과 같이 표시합니다. VF_RotFrame 후처리 도구에 의해 적용되는 다중 블레이드 좌표(MBC) 변환은 이러한 변수를 인식합니다.
