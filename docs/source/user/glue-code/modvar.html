4.2.2. 모듈 변수(ModVar)

해당 ModVar 모듈(modules/nwtc-library/src/ModVar.f90)는 특정 모듈의 내부를 알지 못한 채 글루 코드가 일반적으로 조작할 수 있는 방식으로 각 물리 모듈이 연속 상태, 입력 및 출력을 선언할 수 있도록 하는 데이터 구조와 서브루틴을 제공합니다.

완전한 유형 계층 구조 - DatLoc 및 ModVarType ~을 통해 ModVarsType 및 ModDataType 최상위 수준까지 ModGlueType—에 설명되어 있습니다 그림 4.1.

  • 데이터 구조

    • DatLoc

    • ModVarType

    • ModVarsType

    • ModDataType

  • 변수 플래그(VF_*)

  • 필드 유형(Field*)

  • 모듈 변수 추가

4.2.2.1. 데이터 구조

4.2.2.1.1. DatLoc

A DatLoc (데이터 위치)는 모듈의 파생 유형 계층 내에서 특정 변수가 있는 위치를 고유하게 식별하는 데 사용되는 작은 구조입니다.

TYPE :: DatLoc
  INTEGER :: Num   ! Data identification number (from _Types.f90 file)
  INTEGER :: i1    ! First index
  INTEGER :: i2    ! Second index
  INTEGER :: i3    ! Third index
  INTEGER :: i4
  INTEGER :: i5
END TYPE DatLoc

A DatLoc 값은 레지스트리 생성에 의해 변수당 한 번씩 생성됩니다. DatLoc() 각 모듈 내부의 생성자 호출 InitVars 서브루틴을 거쳐 전달됨 MV_AddVar / MV_AddMeshVar. 글루 코드는 이 값을 각 내부에 저장합니다. ModVarType 그리고 사용 MV_EqualDL 메시 매핑을 설정할 때 소스 및 대상 모듈 전체의 변수를 일치시킵니다.

4.2.2.1.2. ModVarType

단일 변수(또는 메시 필드에 대한 변수 그룹)를 설명합니다.

TYPE :: ModVarType
  INTEGER      :: Field       ! Field type (FieldForce, FieldTransDisp, ...)
  INTEGER      :: Nodes       ! Number of nodes (mesh variables only)
  INTEGER      :: Num         ! Total number of scalar values
  INTEGER      :: Flags       ! Bit-mask of VF_* flags
  INTEGER      :: DerivOrder  ! 0=disp/orientation, 1=velocity, 2=acceleration
  INTEGER      :: iLoc(2)     ! [start, end] in module-local array
  INTEGER      :: iGlu(2)     ! [start, end] in glue-level array
  INTEGER      :: iq(2)       ! [start, end] in solver state (q) array
  INTEGER      :: iLB, iUB    ! User array bounds (for array-valued scalars)
  INTEGER      :: j, k, m, n  ! Additional user-defined indices
  REAL(R8Ki)   :: Perturb     ! Perturbation size for Jacobian finite differences
  TYPE(DatLoc) :: DL          ! Data location
  CHARACTER    :: Name        ! Human-readable variable name
  CHARACTER(:), ALLOCATABLE :: LinNames(:)  ! Per-value linearization labels
END TYPE ModVarType

4.2.2.1.3. ModVarsType

세 그룹으로 나누어진 하나의 모듈에 대한 모든 변수를 보유합니다.

TYPE :: ModVarsType
  INTEGER                             :: Nx, Nu, Ny
  TYPE(ModVarType), ALLOCATABLE :: x(:)   ! Continuous states
  TYPE(ModVarType), ALLOCATABLE :: u(:)   ! Inputs
  TYPE(ModVarType), ALLOCATABLE :: y(:)   ! Outputs
END TYPE ModVarsType

4.2.2.1.4. ModDataType

각 모듈 인스턴스에 대해 글루 코드가 보유하는 최상위 컨테이너:

TYPE :: ModDataType
  CHARACTER    :: Abbr      ! Module abbreviation ("ED", "BD", ...)
  INTEGER      :: iMod      ! Index in glue module array
  INTEGER      :: ID        ! Module_ED, Module_BD, ...
  INTEGER      :: Ins       ! Instance number
  INTEGER      :: iRotor    ! Rotor index (0 = all rotors)
  INTEGER      :: SubSteps  ! Module sub-steps per solver step
  INTEGER      :: Category  ! Bit-mask of MC_* coupling flags
  REAL(R8Ki)   :: DT        ! Module time step
  TYPE(ModVarsType)  :: Vars
  TYPE(ModLinType)   :: Lin
END TYPE ModDataType

4.2.2.4. 모듈 변수 추가

글루 코드에 참여하는 각 모듈은 다음을 구현해야 합니다. InitVars (또는 동등한) 서브루틴을 채우는 ModVarsType 구조를 호출하여 MV_Add* 아래에 문서화된 서브루틴. 이 서브루틴은 모듈이 실행되는 동안 호출됩니다. _Init 루틴과 그 결과 Vars 즉시 전달됩니다. MV_AddModule.

4.2.2.4.1. MV_AddVar

단일(다중 요소 가능) 스칼라 변수를 변수 배열에 추가합니다.

subroutine MV_AddVar(VarAry, Name, Field, DL, &
                     Num, iAry, jAry, kAry, &
                     Flags, DerivOrder, Perturb, LinNames, Active)

논쟁

의지

설명

VarAry

INOUT

할당 가능한 배열 ModVarType; 새 변수가 추가됩니다.

Name

IN

디버그 출력 및 선형화 레이블에 사용되는 사람이 읽을 수 있는 이름입니다.

Field

IN

필드 유형 상수(FieldScalar, FieldTransDisp, 등).

DL

IN

DatLoc 모듈의 파생 유형에서 데이터가 어디에 있는지 식별합니다.

Num

IN (선택 과목)

스칼라 값의 수. 기본값은 1입니다. 0인 경우 통화가 작동하지 않습니다.

iAry

IN (선택 과목)

데이터가 배열에 저장된 경우 하한 인덱스를 시작합니다.

jAry, kAry

IN (선택 과목)

두 번째 및 세 번째 배열 인덱스(2차원 또는 3차원 배열의 경우)

Flags

IN (선택 과목)

초기의 VF_* 플래그 비트 마스크. 기본값은 VF_None.

DerivOrder

IN (선택 과목)

자동으로 추론된 도함수 차수(0, 1 또는 2)를 재정의합니다.

Perturb

IN (선택 과목)

유한차분 섭동 크기. 좋은 기본값은 예상되는 변수 크기의 대략 1%입니다. 메쉬 필드의 경우 기본값은 내부에서 계산됩니다. ModVarType_Init 생략할 때 사용됩니다.

LinNames

IN (선택 과목)

값별 선형화 채널 레이블 배열(길이 = Num). 필수의 메시가 아닌 스칼라 변수가 아닌 경우.

Active

IN (선택 과목)

다음으로 설정 .false. 조건부로 변수 추가를 건너뜁니다.

예 – ServoDyn의 발전기 토크 입력 등록:

call MV_AddVar(Vars%u, 'Generator torque command', FieldScalar, &
               DatLoc(SrvD_u_GenTrq), &
               Flags=VF_Linearize, &
               Perturb=1.0e3_R8Ki, &        ! N*m
               LinNames=['SrvD GenTrq, N*m'])

4.2.2.4.2. MV_AddMeshVar

단일에 대해 요청된 모든 메시 필드를 추가합니다. MeshType 변수 배열에. 주변에 편의를 제공하는 포장지입니다. MV_AddVar 다음을 순회하는 Fields 인수를 적용하고 커밋된 메시에 없는 필드를 건너뜁니다.

subroutine MV_AddMeshVar(VarAry, Name, Fields, DL, Mesh, &
                         Flags, Perturbs, Active, iVar)

논쟁

의지

설명

VarAry

INOUT

새 변수를 추가할 할당 가능한 배열입니다.

Name

IN

이 메시의 모든 필드에 대한 기본 이름입니다.

Fields

IN

필드 유형 상수의 정수 배열. 사용하다 LoadFields, MotionFields, 등 편의 매개변수.

예 – ElastoDyn의 블레이드 루트 출력 모션 메시 등록:

call MV_AddMeshVar(Vars%y, 'BladeRootMotion', MotionFields, &
                   DatLoc(ED_y_BladeRootMotion, i), &   ! blade i
                   p%BladeRootMotion(i), &
                   Flags=VF_Linearize + VF_RotFrame)

4.2.2.4.3. MV_AddModule

모듈 이후 InitVars 서브루틴이 완료되면 호출자는 다음을 사용하여 글루 코드로 모듈을 등록합니다. MV_AddModule.

subroutine MV_AddModule(ModDataAry, ModID, ModAbbr, Instance, &
                        ModDT, SolverDT, Vars, Linearize, &
                        ErrStat, ErrMsg, iRotor)

논쟁

의지

설명

ModDataAry

INOUT

할당 가능한 배열 ModDataType; 새 항목이 추가됩니다.

ModID

IN

모듈 식별자 상수(Module_ED, Module_BD, 등.).

ModAbbr

IN

출력 레이블에 사용되는 짧은 약어 문자열("ED", "BD").

Instance

IN

인스턴스 번호(1 기반). 대부분의 모듈에는 단일 인스턴스가 있습니다.

ModDT

IN

모듈 시간 단계(초)입니다. 다음의 정확한 정수 제수여야 합니다. SolverDT.

SolverDT

IN

솔버(전역) 시간 단계입니다.

Vars

IN

인구가 많은 ModVarsType 해당 모듈의 InitVars 부르다.

Linearize

IN

선형화가 활성화되어 있는지 여부입니다. 언제 .false., LinNames 메모리를 절약하기 위해 배열 할당이 취소됩니다.

ErrStat / ErrMsg

OUT

오류 상태 및 메시지.

iRotor

IN (선택 과목)

다중 로터 터빈의 로터 번호(0 = 모든 로터).

하위 스테핑 논리: 만약에 ModDT < SolverDT, MV_AddModule 계산하다 ModData%SubSteps = NINT(SolverDT/ModDT) 모듈 DT가 솔버 DT를 정확하게 분할하는지 검증합니다. 다음과 같은 경우 오류가 반환됩니다. ModDT > SolverDT.

FAST_Subs.f90 내부의 일반적인 호출 순서:

! Module computes its own Vars in Init
call ED_Init(InitInp, u, p, ..., InitOut, ErrStat, ErrMsg)
! Register with glue code
call MV_AddModule(m%ModData, Module_ED, 'ED', 1, p%DT, p_FAST%DT, &
                  InitOut%Vars, p_FAST%Linearize, ErrStat, ErrMsg, iRotor=1)

4.2.2.5. 섭동 값

모든 변수는 Perturb 모듈 수준 야코비 행렬을 작성할 때 중심차 유한 차분에 사용되는 값입니다. 그만큼 Perturb 주장 MV_AddVar / MV_AddMeshVar 결과적인 출력 변화가 수치적 잡음과 구별될 만큼 충분히 크지만 선형 체제를 유지할 만큼 충분히 작도록 선택해야 합니다. 일반적인 값:

  • 번역 변위: 1.0e-4 m

  • 회전(방향): 2.0e-5 라드

  • 번역 속도: 1.0e-3 m/s

  • 각속도: 2.0e-4 라드/초

  • 번역 가속화: 1.0e-2 m/s²

  • 힘: 1.0e1 N

  • 순간: 1.0e1 N·m

  • 일반 스칼라: 상황에 따라 다름

해당 UJacSclFact 입력 매개변수(참조 사용자 입력 매개변수)는 힘/모멘트 크기가 상태 크기와 매우 다를 때 매트릭스 조건을 개선하기 위해 솔버가 야코비 행렬의 부하 변수에 적용하는 전역 조건 요인입니다.

4.2.2.6. 방향 표현

오리엔테이션은 ~ 아니다 글루 변수 배열 내부에 방향 코사인 행렬(DCMs)로 저장되거나 조작됩니다. 대신, 컴팩트한 3개 구성요소 단위 쿼터니언 매개변수화가 사용됩니다.

\[\mathbf{q}_p = [q_1, q_2, q_3] \quad \text{where } q_0 = \sqrt{1 - q_1^2 - q_2^2 - q_3^2}\]

이 매개변수화는 전체 DCM의 중복을 방지하고 쿼터니언 합성을 통해 간단한 유한 차분을 가능하게 합니다(quat_compose). 다음에서 내보낸 변환 유틸리티 ModVar 포함하다 dcm_to_quat, quat_to_dcm, quat_compose, quat_inv, quat_to_rvec, rvec_to_quat, wm_to_quat, 및 quat_to_wm.

야코비안 행의 방향 차이를 계산할 때, MV_ComputeDiff 음의 섭동 쿼터니언과 양의 섭동 쿼터니언 사이의 상대 회전을 계산하고 이를 회전 벡터로 변환합니다.
