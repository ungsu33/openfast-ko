4.13.5. 사용자 정의 바람 필드

이 섹션에서는 다음을 사용하여 InflowWind에서 사용자 정의 바람 필드를 구현하는 방법을 설명합니다. WindType = 6.

4.13.5.1. 개요

사용자 정의 바람 필드 기능을 통해 개발자는 다음을 통해 사용자 정의 바람 모델을 구현할 수 있습니다.

  1. 바람 필드 매개변수를 보유하는 데이터 구조 정의

  2. 입력 파일 또는 매개변수에서 해당 데이터 구조 초기화

  3. 임의의 위치, 시간의 풍속을 반환하는 기능 구현

이는 다음에 유용합니다.

  • 해석적 바람 모델(예: 소용돌이, 후류 모델)

  • 맞춤형 바람 프로필은 표준 형식으로 사용할 수 없습니다.

  • 외부 바람 솔버에 대한 커플링

  • 센서를 통한 실시간 바람 측정

  • 새로운 바람장 표현 연구 및 개발

중요

레지스트리 파일을 수정한 후(.txt 파일), 유형 정의 파일(*_Types.f90). 수정 사항은 .txt 파일은 확장된 데이터 구조를 정의하지만 재생성이 완료될 때까지 사용할 수 없습니다.

4.13.5.2. 구현 단계

4.13.5.2.1. 1단계: 데이터 구조 정의

편집 modules/inflowwind/src/IfW_FlowField.txt 및 필드 추가 UserFieldType:

typedef  ^              UserFieldType          ReKi                RefHeight           -     -         -     "reference height; used to center the wind"                   meters
typedef  ^              ^                      IntKi               NumDataLines        -     0         -     "number of data lines (for time-varying user wind)"          -
typedef  ^              ^                      DbKi                DTime               :     -         -     "time array for user-defined wind"                           seconds
typedef  ^              ^                      ReKi                Data                ::    -         -     "user-defined wind data array [NumDataLines, NumDataColumns]" -
typedef  ^              ^                      CHARACTER(1024)     FileName            -     -         -     "name of user wind file (if applicable)"                     -

바람 모델 구현에 필요한 사용자 정의 필드를 추가합니다.

4.13.5.2.2. 2단계: 초기화 입력 정의

편집 modules/inflowwind/src/InflowWind_IO.txt 및 필드 추가 User_InitInputType:

typedef  ^              User_InitInputType    CHARACTER(1024)         WindFileName            -     -     -     "name of file containing user-defined wind data (if applicable)" -
typedef  ^              ^                     ReKi                    RefHt                   -     -     -     "reference height for user wind field"                        meters
typedef  ^              ^                     IntKi                   NumDataColumns          -     0     -     "number of data columns in user wind file (if applicable)"    -

바람 모델을 초기화하는 데 필요한 매개변수를 추가하세요.

4.13.5.2.3. 3단계: 유형 파일 재생성

레지스트리 파일을 수정한 후 프로젝트를 다시 빌드하여 유형 정의를 다시 생성하십시오. Visual Studio를 사용하여 Windows에서 OpenFAST를 빌드하면 형식 파일이 자동으로 다시 생성됩니다. CMake를 사용하는 경우 다음 명령을 실행하여 유형 파일 생성을 활성화합니다.

cd build
cmake .. -DGENERATE_TYPES=ON
make

빌드 프로세스는 자동으로 *_Types.f90 파일은 .txt 레지스트리 파일.

4.13.5.2.4. 4단계: 초기화 구현

편집 modules/inflowwind/src/InflowWind_IO.f90 및 구현 IfW_User_Init():

subroutine IfW_User_Init(InitInp, SumFileUnit, UF, FileDat, ErrStat, ErrMsg)
   ! Initialize UF%RefHeight, read data files, allocate arrays
   ! Set FileDat metadata (wind type, time range, spatial extent, etc.)
   ! Write summary information to SumFileUnit if > 0
end subroutine

이 루틴은 다음과 같습니다.

  • 에 지정된 필수 입력 파일을 읽습니다. InitInp

  • 할당하고 채웁니다. UserFieldType (UF) 데이터 구조

  • 다음에 적절한 메타데이터를 설정합니다: WindFileDat 구조

  • 요약 파일에 초기화 정보를 씁니다.

4.13.5.2.5. 5단계: 속도 기능 구현

편집 modules/inflowwind/src/IfW_FlowField.f90 및 구현 UserField_GetVel():

subroutine UserField_GetVel(UF, Time, Position, Velocity, ErrStat, ErrMsg)
   ! Use UF data to compute velocity at Position and Time
   ! Position(1) = X, Position(2) = Y, Position(3) = Z (meters)
   ! Return Velocity(1) = U, Velocity(2) = V, Velocity(3) = W (m/s)
end subroutine

이 함수는 시뮬레이션 중에 풍속이 필요한 각 위치에 대해 호출됩니다.

4.13.5.3. 좌표계

4.13.5.3.1. 입력 좌표(위치)

  • X: 다운스트림 방향(InflowWind에 의해 회전이 적용된 후)

  • Y: 측면/측풍 방향

  • Z: 수직 방향(지면에서 측정, Z=0은 지면 수준)

  • 장치: 미터

4.13.5.3.2. 출력 속도(Velocity)

  • U: X를 따른 속도 구성요소(양수 = 하향풍)

  • V: Y 방향의 속도 구성요소(양수 = 바람이 불어오는 방향을 볼 때 왼쪽)

  • W: Z 방향의 속도 구성요소(양수 = 위쪽)

  • 장치: m/s

참고

InflowWind는 전역 좌표와 바람 좌표 간의 회전을 처리합니다. 구현은 X가 평균 풍향과 정렬되는 바람 좌표계에서 작동해야 합니다.

4.13.5.4. 예시 구현

4.13.5.4.1. 멱법칙 바람 프로필

이 예에서는 간단한 거듭제곱 법칙 바람 프로필을 구현합니다.

속도 기능 (에서 IfW_FlowField.f90):

subroutine UserField_GetVel(UF, Time, Position, Velocity, ErrStat, ErrMsg)
   type(UserFieldType), intent(in)     :: UF
   real(DbKi), intent(in)              :: Time
   real(ReKi), intent(in)              :: Position(3)
   real(ReKi), intent(out)             :: Velocity(3)
   integer(IntKi), intent(out)         :: ErrStat
   character(*), intent(out)           :: ErrMsg

   real(ReKi)                          :: RefSpeed, Exponent, Height

   ErrStat = ErrID_None
   ErrMsg = ""

   ! Get reference speed and exponent from UF%Data
   RefSpeed = UF%Data(1, 1)  ! Reference wind speed (m/s)
   Exponent = UF%Data(1, 2)  ! Power law exponent
   Height = Position(3)       ! Height above ground

   ! Apply power law: U(z) = Uref * (z/zref)^alpha
   if (Height > 0.0_ReKi) then
      Velocity(1) = RefSpeed * (Height / UF%RefHeight)**Exponent
      Velocity(2) = 0.0_ReKi  ! No lateral wind
      Velocity(3) = 0.0_ReKi  ! No vertical wind
   else
      Velocity = 0.0_ReKi  ! Below ground
   end if

end subroutine

초기화 (에서 InflowWind_IO.f90):

subroutine IfW_User_Init(InitInp, SumFileUnit, UF, FileDat, ErrStat, ErrMsg)
   ! ... (declarations)

   ErrStat = ErrID_None
   ErrMsg = ""

   ! Set reference height
   UF%RefHeight = InitInp%RefHt

   ! Allocate data array for [RefSpeed, Exponent]
   UF%NumDataLines = 1
   call AllocAry(UF%Data, 1, 2, 'User wind data', TmpErrStat, TmpErrMsg)
   call SetErrStat(TmpErrStat, TmpErrMsg, ErrStat, ErrMsg, RoutineName)
   if (ErrStat >= AbortErrLev) return

   ! Set values (could read from file instead)
   UF%Data(1, 1) = 10.0_ReKi  ! 10 m/s reference speed
   UF%Data(1, 2) = 0.2_ReKi   ! Power law exponent

   ! Set metadata
   FileDat%WindType = 6
   FileDat%RefHt = UF%RefHeight
   FileDat%MWS = UF%Data(1, 1)
   FileDat%RefHt_Set = .true.
   ! ... (set other FileDat fields as needed)

end subroutine

4.13.5.5. 일반적인 사용 사례

4.13.5.5.1. 꾸준한 분석 바람 필드

바람을 위치의 함수로만 정의합니다(무시 Time 매개변수).

예: 로그 바람 프로필, 소용돌이 바람 필드, 전단력이 있는 균일 흐름.

4.13.5.5.2. 시변 바람장

시계열 배열에 바람 데이터를 저장하고 다음을 기반으로 보간합니다. Time 매개변수.

예: 측정된 바람 데이터, 규정된 바람 과도 현상, 항적 모델. 외부 솔버의

4.13.5.5.3. 바람

외부 함수를 호출하여 순간적인 바람장을 얻습니다.

예: CFD 커플링, 외부 후류 모델, 규정 난류.

4.13.5.5.4. 실시간 센서 데이터

센서에서 측정된 바람 데이터를 로드하고 공간/시간적으로 보간합니다.

예: LIDAR 측정, 마스트 데이터, 현장 측정.

4.13.5.6. 제한 사항 및 고려 사항

4.13.5.6.1. 전류 제한

  1. 가속 지원 없음: 사용자 정의 바람 필드는 현재 일부 모듈(예: MHK 터빈)에 필요한 가속도 계산을 지원하지 않습니다.

4.13.5.6.2. 성능 고려 사항

  • UserField_GetVel() 는 모든 시간 단계의 모든 지점에 대해 호출됩니다.

  • 효율적으로 구현하십시오. 값을 미리 계산 가능한 경우 IfW_User_Init() 가능한 경우

  • 복잡한 계산을 위한 캐싱 또는 보간 전략을 고려하십시오.

4.13.5.6.3. 오류 처리

  • 항상 입력 매개변수의 유효성을 검사합니다. IfW_User_Init()

  • 배열 경계를 확인하세요. UserField_GetVel()

  • 위치 및 시간 값이 유효한 범위 내에 있는지 확인하십시오. 오류를 적절하게 보고하려면

  • 사용 디버거와 함께 사용할 디버그 기호를 추가하기 위해 활성 개발 중에 SetErrStat() 를 사용하세요.

4.13.5.7. 모범 사례

  1. 간단하게 시작: 복잡한 바람장을 구현하기 전에 분석 모델부터 시작하세요.

  2. 문서를 철저하게 작성하세요: 구현 및 파일 형식을 설명하는 자세한 설명을 추가하세요.

  3. SI 단위 사용: 항상 미터, 초, m/s를 사용합니다.

  4. 사전 계산: 런타임보다는 초기화 중에 최대한 많이 계산

  5. 검증: 생산에 사용하기 전에 알려진 분석 솔루션으로 테스트

  6. 핸들 경계: 유효한 도메인 외부의 포인트에 대해 적절한 동작 구현

  7. 보고서 메타데이터: 올바르게 채우기 시간 범위, 공간 범위 등이 포함된 WindFileDat 시간 범위, 공간 범위 등의 정보를 포함하여
