4.9.2. 입력 파일

이 섹션에서는 ExtPtfm에서 사용되는 다양한 입력 파일에 대해 설명합니다. ExtPtfm은 SI 시스템(kg, m, s, N)을 사용합니다. 입력 파일에 줄을 추가하거나 제거하면 안 됩니다.

4.9.2.1. ExtPftm 모듈 입력 파일

OpenFAST 2.3 이전에는 ExtPtfm 모듈에 "모듈" 입력 파일이 없었고 Guyan ASCII 입력 파일이 직접 제공되었습니다. 이는 더 이상 지원되지 않으며 모듈 입력 파일이 필요합니다. 예 ExtPtfm을 사용한 OpenFAST 설정은 여기에서 사용할 수 있습니다.. 예 ExtPtfm 모듈 입력 파일은 여기에서 사용할 수 있습니다.. 형식은 다른 것과 비슷하다. OpenFAST 모듈. 입력 매개변수는 다음과 같습니다.

  • DT: 수치 적분을 위한 시간 단계입니다. 사용자는 여기에서 시간 단계를 지정하거나 "기본값"을 사용하여 글루 코드 시간 단계에 의존할 수 있습니다.

  • IntMethod: 시간 적분을 위한 수치적 방법. Runge-Kutta, Adams–Bashforth 및 Adams–Bashforth-Moutlon 방법을 사용할 수 있습니다.

    RBMod: 부유 구조물의 강체 운동을 처리하는 방법(스위치). 0: 강체 모션(바닥 고정 구조)에 대한 특별한 처리가 없습니다. 1: 강체 참조 프레임으로 변환합니다. 2: 강체 기준 프레임으로 변환하고 가상의 힘과 정확한 자중을 추가합니다.

  • Red_Filename: Guyan/Craig-Bampton 입력이 포함된 파일의 경로입니다.

  • ActiveDOFList: 사이즈 목록 활성화된 CB 모드 인덱스를 포함하는 NActiveDOFList . 다음 경우에는 이 목록을 읽을 수 없습니다. NActiveDOFList<=0. 지정되면 모든 시스템 행렬의 모양이 다음과 같이 변경됩니다. \(\boldsymbol{M}_\text{new}=\boldsymbol{M}(I,I)\) 여기서 \(I\) 는 잠재적으로 정렬되지 않고 연속되지 않은 인덱스 목록입니다. 설정 NActiveDOFList=0 는 Guyan 축소와 동일합니다. 설정 \(\texttt{NActiveCBDOF}=-1\) 는 입력 파일에 제공된 모든 CB DOF를 사용합니다. CB 모드의 초기 위치를 포함하는

  • InitPosList: 사이즈 목록 활성화된 CB 모드 인덱스를 포함하는 NInitPosList . 다음 경우에는 이 목록을 읽을 수 없습니다. NInitPosList<=0, 이 경우 모든 CB DOF 위치는 0으로 초기화됩니다. CB 모드의 초기 속도를 포함하는

  • InitVelList: 사이즈 목록 활성화된 CB 모드 인덱스를 포함하는 NInitVelList . 다음 경우에는 이 목록을 읽을 수 없습니다. NInitVelList<=0, 이 경우 모든 CB DOF 속도는 0으로 초기화됩니다.

    Connections: 구조에 연결점을 포함하기 위한 플래그입니다. true인 경우 연결을 지정하는 파일이 다음을 통해 제공되어야 합니다. Conn_FileName. 현재 이 기능은 계류 모듈 중 하나와 연결하는 데에만 사용됩니다.

    UserForcing: 사용자 정의 모달 강제에 대한 플래그입니다. true인 경우 적용할 강제 시계열이 포함된 파일을 다음을 통해 제공해야 합니다. Force_FileName.

    ConnForcing: 연결점에서 사용자 정의 외력에 대한 플래그입니다. true인 경우 연결 지점에 적용할 힘 시계열이 포함된 파일을 다음을 통해 제공해야 합니다. FConn_FileName. 이 옵션에는 Connections 는 사실입니다. 모멘트 적용은 지원되지 않습니다.

  • SumPrint: 요약 데이터를 <RootName>.sum으로 인쇄합니다.

  • OutFile , TabDelim, OutFmt, TStart: 출력 플래그, 현재 사용되지 않음

  • OutList: 사용자가 요청하는 출력 목록을 지정합니다. 이러한 출력은 다음 항목에 설명되어 있습니다. 출력 채널.

4.9.2.3. Guyan/Craig-Bampton 수퍼엘리먼트 입력 파일(다음을 통해 제공됨) Red_Filename)

이 수퍼엘리먼트 입력 파일은 시스템 행렬을 제공하는 데 사용됩니다.

4.9.2.3.1. 예

슈퍼 요소 파일의 예를 사용할 수 있습니다 여기. 아래에는 숫자 값이 암시된 "모형" 예가 나와 있습니다. n, M(i,j), K(i,j), C(i,j)등

!Comment
!Comment
!Dimension: n

!Mass Matrix (Units (kg,m))
  M(1,1) ... M(1,n)
        [...]
  M(n,1) ... M(n,n)

!Stiffness Matrix (Units (N,m))
  K(1,1) ... K(1,n)
        [...]
  K(n,1) ... K(n,n)

!Damping Matrix (Units (N,m,kg))
  C(1,1) ... C(1,n)
        [...]
  C(n,1) ... C(n,n)

!Weight constant (Units (N,m))
  W_0(1) W_0(2) ... W_0(n)

!Weight stiffness (Units (N,m))
  K_W(1,1) ... K_W(1,n)
          [...]
  K_W(n,1) ... K_W(n,n)

4.9.2.3.2. 사양

파일은 다음 사양을 따릅니다.

  • ASCII 파일

  • 파일은 느낌표 '로 시작하는 임의 수의 주석 줄로 시작할 수 있습니다.!‘

  • 다음(대소문자 구분 안 함) 키워드를 다음에 제공해야 합니다.

    • ‘!dimension:' 뒤에 정수가 옵니다. n\(=6+n_{CB}\)

  • 나머지 줄은 다음과 같은 특수(대소문자 구분) 키워드로 구성됩니다.

    • ‘!mass matrix': 뒤에 일부 텍스트가 옵니다. 다음 \(n\) 라인은 각각 다음을 포함합니다. \(n\) 부동 소수점 값. 이 값은 다음에 해당합니다. \(\boldsymbol{M}_r\). 다음을 사용하여 부유 구조물을 모델링할 때 주의하세요. RBMod > 0, 인터페이스 모드인 처음 6개 모드는 강체 모드로도 사용됩니다. 따라서 의 처음 6x6 항목은 \(\boldsymbol{M}_r\) 는 일관된 강체 질량 매트릭스여야 합니다. ExtPtfm은 그렇지 않은 경우 경고를 표시합니다. 내부적으로 ExtPtfm은 이 정보를 사용하여 질량, 강체 관성 모멘트 및 CoG 위치를 결정합니다.

    • ‘!stiffness matrix': 질량 행렬과 유사하며 값은 다음에 해당합니다. \(\boldsymbol{K}_r\). 부유 구조물의 경우 강체 운동과 관련된 구조적 강성이 없어야 합니다. 따라서 처음 6개 행과 6개 열은 \(\boldsymbol{K}_r\) 는 모두 0이어야 합니다.

    • ‘!weight constant': 뒤에 일부 텍스트가 옵니다. 다음 줄에는 다음이 포함되어야 합니다. \(n\) 부동 소수점 값. 값은 일정한 자중과 일치합니다. \(\boldsymbol{W}_0\). 플로팅 구조의 경우 첫 번째, 두 번째, 여섯 번째 항목은 다음과 같습니다. \(\boldsymbol{W}_0\) 는 0이어야 합니다. 자중으로 인한 일정한 롤 및 피치 모멘트는 질량 매트릭스에서 파생된 CoG 위치와 일치해야 합니다.

    • ‘!weight stiffness': 질량 행렬과 유사하며 값은 다음에 해당합니다. \(\boldsymbol{K}_W\). 부유식 구조물의 경우 채택된 협약에서는 다음을 요구합니다. \(\boldsymbol{W}_0\) - \(\boldsymbol{K}_W\) *(모달 변위)는 강체/인터페이스 동작에 따라 참조 프레임에 자중을 반환합니다. 이는 다음의 항목 (1,5)을 의미합니다. \(\boldsymbol{K}_W\) 는 다음과 같아야 합니다. \(\boldsymbol{W}_0(3)\). 항목 (2,4)는 다음과 같아야 합니다. \(-\boldsymbol{W}_0(3)\). 항목 (4,4)와 (5,5)는 다음과 같아야 합니다. \(\boldsymbol{W}_0(3) * z_{CG}\). 항목 (6,4)는 다음과 같아야 합니다. \(-\boldsymbol{W}_0(3) * x_{CG}\), 항목 (6,5)는 다음과 같아야 합니다. \(-\boldsymbol{W}_0(3) * y_{CG}\), 여기서 \((x_{CG},y_{CG},z_{CG})\) 는 ElastoDyn에 정의된 플랫폼 기준점에서 측정된 강체 질량 중심의 위치입니다. 즉, (PtfmRefxt, PtfmRefyt, PtfmRefzt). 1, 2, 6열의 모든 항목 \(\boldsymbol{K}_W\) 는 0이어야 합니다. 다시 말하지만, 입력 행렬이 이 구조를 따르지 않으면 경고가 표시됩니다.

4.9.2.4. 연결 입력 파일(다음을 통해 제공됨) Conn_Filename)

연결 입력 파일은 구조의 연결점 수와 위치를 제공하는 데 사용됩니다. 현재 연결 지점은 사용 가능한 계류 모듈이 활성화된 경우 계류 페어리드와 연결하는 데에만 사용됩니다. 또한 이 파일은 각 Guyan 모드 및 Craig-Bampton 모드에 대한 각 연결점에서 구조적 동작/편향을 제공해야 합니다.

4.9.2.4.1. 예

아래에는 숫자 값이 암시된 "더미" 예가 나와 있습니다. m, X1, Y1, Z1등

!Comment
!Comment
!nConn: m

!Connections (m)
  X1  Y1  Z1
     [...]
  Xm  Ym  Zm

!Displacement (m)
  [3m x n matrix]

4.9.2.4.2. 사양

파일은 다음 사양을 따릅니다.

  • ASCII 파일

  • 파일은 느낌표 '로 시작하는 임의 수의 주석 줄로 시작할 수 있습니다.!‘

  • 다음(대소문자 구분 안 함) 키워드는 지정된 순서대로 다음에 제공되어야 합니다. 구조의 연결점 수를 제공하는

    • ‘!nConn:' 뒤에 정수가 옵니다. m 각각 3개의 부동 소수점 값을 포함하는

    • ‘!Connections': 뒤에 일부 텍스트가 옵니다. 다음 \(m\) 라인은 다음을 제공합니다. \(x\), \(y\)및 이 플래그 값 아래에 \(z\) 좌표 \(m\) 연결 지점. 좌표는 예를 들어 HydroDyn 및 MoorDyn 입력 파일에 사용된 것과 동일한 전역 원점을 참조하며 ElastoDyn에 정의된 플랫폼 참조점과 관련이 없습니다.

    • ‘!Displacement': 뒤에 일부 텍스트가 옵니다. 다음 \(3m\) 라인은 각각 다음을 포함합니다. \(n\) 부동 소수점 값. 이 행렬의 열은 다음에 해당합니다. 슈퍼 요소 입력 파일에 정의된 \(n\) 모드를 제공하고 \(x\), \(y\)및 이 플래그 값 아래에 \(z\) 각 모드의 단위 운동에 대해 처음 3행의 첫 번째 연결점 변위, 다음 3행의 두 번째 연결점 변위 등입니다. 부유체를 모델링할 때 RBMod > 0, 처음 6개 모드는 강체 모드로도 사용되는 Guyan 인터페이스 모드입니다. 따라서 이 행렬의 처음 6개 열은 ElastoDyn에 정의된 플랫폼 기준점을 따르는 각 연결점의 선형화된 강체 모션을 간단히 설명해야 합니다. 즉, (PtfmRefxt, PtfmRefyt, PtfmRefzt).

4.9.2.5. 사용자 모달 및 연결 강제 파일(다음을 통해 제공됨) Force_Filename 및 FConn_Filename )

이 두 파일을 통해 사용자는 시스템 모드 및 연결 지점에 대한 외부 강제를 규정할 수 있습니다. 두 파일의 형식은 비슷합니다. 유일한 차이점은 열 수입니다.

4.9.2.5.1. 예

아래에는 숫자 값이 암시된 "더미" 예가 나와 있습니다. k, t1, F1등

!Comment
!Comment
!nSteps: k

!Forcing (N/-)
  t(1)  F_1(1)  F_2(1) ...
        [...]
  t(k)  F_1(k)  F_2(k) ...

4.9.2.5.2. 사양

파일은 다음 사양을 따릅니다.

  • ASCII 파일

  • 파일은 느낌표 '로 시작하는 임의 수의 주석 줄로 시작할 수 있습니다.!‘

  • 다음(대소문자 구분) 키워드는 제공된 순서대로 다음에 제공되어야 합니다. 힘 시계열의 시간 단계 수를 제공하는

    • ‘!NSteps:' 뒤에 정수가 옵니다. k 힘 시계열의 시간 단계 수를 나타내며

    • ‘!Forcing': 뒤에 일부 텍스트가 옵니다. 다음 \(k\) 라인은 사용자 정의 모달 또는 연결 강제 시계열을 제공합니다. 열 수는 이것이 모달 강제인지 연결 강제인지에 따라 달라집니다. 두 경우 모두 첫 번째 열은 시간입니다. 모달 강제력의 경우 다음이 있어야 합니다. 시간 열 뒤에 오는 \(n\) 열. 각 열은 수퍼 요소 입력 파일에 정의된 모드 중 하나에 해당합니다. 연결 강제를 위해서는 다음이 있어야 합니다. 시간 열 다음에 \(3m\) 열이 표시됩니다. \(x\), \(y\)및 이 플래그 값 아래에 \(z\) 힘 구성요소는 두 번째 연결점의 구성요소로 이어집니다. 첫 번째 열의 시간은 시뮬레이션 시간 단계와 일치하거나 간격이 균등할 필요가 없습니다. ExtPtfm은 필요에 따라 제공된 시간 사이에 선형 보간을 수행합니다.
