4.1.3. 입력 파일 형식

OpenFAST는 두 가지 기본 입력 파일 형식을 사용합니다. 값 열 각 줄의 첫 번째 값을 읽는 방식이며, 키+값 여기서 값과 키워드 쌍을 읽습니다. 두 형식 모두 일부 예외를 제외하고 특정 줄에서 특정 입력이 예상되는 위치를 기반으로 하는 줄 번호입니다.

4.1.3.1. 값 열 입력 파일

첫 번째 열만 값 열 기반 입력 파일을 읽습니다. 이는 OpenFAST 및 이전 버전에서 사용된 기록 형식입니다(키워드는 소스 코드 및 문서에서 자주 참조되었지만 OpenFAST는 키워드 또는 설명을 처리하지 않았습니다). 첫 번째 값을 읽은 이후의 모든 내용은 코드에서 무시됩니다. 이를 통해 사용자는 항목을 수정하는 동안 이전 값을 유지할 수 있었습니다. 예를 들어 다음과 같은 입력 라인은

2       20   TMax            - Total run time (s)

다음과 같이 읽혀질 것이다 2 그리고 20 그 이후의 모든 것은 무시되었습니다.

이 형식 및 관련 구문 분석 방법은 사용자에게 구문 분석 오류를 알리는 데 다소 제한이 있으며 전체 입력 파일을 다른 코드(예: Python 드라이버 코드)의 텍스트 문자열로 전달하는 기능도 제한됩니다.

4.1.3.2. 키 + 값 입력 파일

처음 두 열을 읽습니다. 키 + 값 입력 파일. 두 열 중 하나에는 다음이 포함되어야 합니다. 정확한 키워드이고 다른 하나는 이에 해당하는 값을 포함해야 합니다. 예를 들어, 입력 라인

20   TMax            - Total run time (s)

는 다음과 같습니다

TMax         20            - Total run time (s)

이 입력 파일 형식의 추가 기능 중 하나는 사용자가 원하는 위치에 임의 수의 주석 줄을 추가하는 기능입니다. 다음으로 시작하는 모든 줄 !, #, 또는 % 주석 줄로 처리되어 무시됩니다. 예를 들어,

! This is a comment line that will be skipped
        %  and this is also a comment line that will be skipped
# as is this comment line
       20   TMax            - Total run time (s)
! the first two columns in the above line will be read as the value + key

이 형식의 입력 파일에 대한 구문 분석기는 어떤 줄이 주석인지, 어떤 줄에 값과 키 쌍이 포함되어 있는지도 추적합니다. 키 이름을 찾을 수 없으면 파서는 어느 줄에서 읽었는지에 대한 정보와 함께 오류를 반환합니다.

4.1.3.2.2. 변경 이유

입력 파일 구문 분석이 변경된 주요 이유는 메모리의 전체 입력 파일을 래퍼 코드에서 OpenFAST 또는 모듈로 전달할 수 있도록 하기 위한 것이었습니다. 예를 들어 AeroDyn 모듈을 Python 코드에 포함하면 먼저 디스크에 쓰지 않고도 입력 파일을 메모리에 직접 전달할 수 있습니다. 이는 입력 파일에 대한 아주 작은 변경으로 모듈이 순차적으로 여러 번 호출될 수 있는 최적화 루프에서 IO 오버헤드를 줄이는 데 도움이 됩니다. NOTE: 아직 진행 중인 작업이므로 아직 모든 모듈을 이 방식으로 연결할 수는 없습니다..

이를 달성하기 위해 AeroDyn 15의 FAST8에 있는 익형 테이블을 구문 분석하기 위해 Marshall Buhl이 작성한 파일 파서가 사용되었습니다. 이 파서는 더욱 강력한 기능을 포함했습니다. 키 + 값 입력 형식.

4.1.3.3. 입력 파일 문제 해결

입력 파일 오류 문제를 해결할 때 다음 절차를 시도해 보십시오.

  1. 줄 번호와 변수 이름이 포함된 오류 메시지, 구문 분석되는 파일 형식은 키 + 값 체재. 키의 철자가 입력 파일과 정확히 일치하는지 확인하세요. 보다 섹션 4.1.3.2 아래에.

  2. 변수 이름만 포함되고 줄 번호가 없는 오류 메시지는 값 열 입력 파일 형식. 보다 섹션 4.1.3.1 아래에.

  3. 켜다 에코 입력 파일의 옵션을 선택하고 결과를 확인하십시오. .ech 파일 구문 분석이 중지된 줄입니다. 이는 오류 메시지에 줄 번호가 제공되지 않을 때 입력 파일 구문 분석이 실패한 위치를 격리하는 데 도움이 될 수 있습니다.

  4. 문제가 있는 입력 파일을 OpenFAST와 함께 배포된 회귀 테스트 모음의 동일한 유형의 입력 파일과 비교합니다. 섹션을 참조하세요 섹션 5 회귀 테스트에 대한 자세한 내용을 알아보거나 다음 저장소를 확인하세요. r-테스트 .
