5. OpenFAST 테스트

OpenFAST는 움직이는 부품이 많은 복잡한 소프트웨어입니다. 신규 코드와 기존 코드의 안정성을 유지하기 위해 테스트 스위트가 소스 코드에 직접 포함됩니다. 테스트에는 두 가지 기본 수준이 있습니다. 가장 높은 수준의 회귀 테스트와 가장 낮은 수준의 단위 테스트입니다. 회귀 테스트는 로컬에서 생성된 결과를 저장된 "기준" 결과와 비교합니다. 이러한 테스트는 전체 시스템 또는 하위 시스템 응답이 변경되었는지 여부를 나타냅니다. 단위 테스트는 단일 서브루틴 또는 코드 블록에 중점을 둡니다. 이러한 테스트는 물리적으로 현실적일 필요는 없으며 알고리즘의 수학과 실행에 중점을 둡니다. 포함된 테스트의 목적은 결과에서 버그나 예상치 못한 변화를 신속하게 찾아내는 것입니다. 또한 이 테스트는 프로그래머가 지속 가능하고 유지 관리 가능한 방식으로 모듈 및 서브루틴 인터페이스를 설계하는 데 도움이 될 수 있습니다.

회귀 테스트에 해당하는 필요한 모든 파일은 reg_tests 예배 규칙서. 단위 테스트 프레임워크는 다음 위치에 있습니다. unit_tests 실제 테스트는 테스트된 모듈에 해당하는 디렉터리에 포함되어 있습니다.

OpenFAST GitHub 저장소는 다음을 사용합니다. GitHub 작업 새로운 커밋 및 풀 요청에 대한 테스트 스위트를 자동으로 실행합니다. 이 클라우드 컴퓨팅 리소스는 모든 GitHub 사용자가 사용할 수 있으며 개발 작업 흐름의 일부로 적극 권장됩니다. OpenFAST 저장소에서 GitHub 작업을 활성화한 후 새 커밋을 푸시하기만 하면 테스트가 트리거됩니다.

5.3. 테스트 스위트 확보 및 구성

테스트 스위트의 일부는 다음을 통해 OpenFAST 저장소에 연결됩니다. 자식 하위 모듈. 특히 다음 저장소가 포함됩니다.

  • r-테스트

팁

다음을 사용하여 저장소를 복제하십시오. --recursive 플래그 또는 실행 git submodule update --init --recursive 복제 후.

테스트 스위트는 추가 CMake 플래그를 사용하여 일반 OpenFAST 빌드 프로세스와 유사한 CMake로 구성됩니다.

# BUILD_TESTING     - Build the testing tree (Default: OFF)
cmake .. -DBUILD_TESTING:BOOL=ON

이 플래그 외에도 기본 CMake 구성은 대부분의 시스템에 적합합니다. 참조 CMake 이해 CMake 대상 구성에 대한 자세한 내용은 섹션을 참조하세요. 단위 테스트는 다음 항목에 대한 종속성으로 인해 CMake를 사용하여 구축해야 합니다. test_drive (소스 코드에 포함됨) 회귀 테스트는 CMake 없이 실행될 수 있습니다. Python 드라이버로 실행.
