5.2. 회귀 테스트

회귀 테스트는 OpenFAST 및 해당 모듈의 기능을 완전히 설명하기 위한 일련의 테스트 사례를 실행합니다. 회귀 테스트 실행에 대한 지침을 보려면 다음 섹션 중 하나로 이동하세요.

  • Python 드라이버로 실행

  • CTest로 실행

  • 회귀 테스트 예

  • Visual Studio 회귀 테스트를 사용하는 Windows

로컬에서 계산된 각 결과는 기본 결과의 정적 세트와 비교됩니다. 결과는 다음 OS, 컴파일러 및 하드웨어 조합을 사용하여 계산됩니다.

운영 체제

컴파일러

하드웨어

우분투 22.04

GNU 12.3.0

GitHub 작업

회귀 테스트를 로컬에서 실행하는 경우 컴파일러와 하드웨어 조합으로 인해 몇 가지 테스트가 실패할 수 있는 작은 수치 차이가 있을 수 있습니다. 당신이 사용하는 경우 bokeh 테스트를 실행하는 동안 패키지를 실행하면 결과가 표시됩니다. HTML 실패한 테스트의 차이점을 보여주는 플롯이 있는 파일(이러한 차이는 작아야 함)

기본 솔루션을 생성하는 데 사용되는 컴파일러 버전, 특정 수학 라이브러리 및 하드웨어에 대한 자세한 정보는 r-test 저장소 문서. 현재 회귀 테스트는 배정밀도 빌드만 지원합니다.

회귀 테스트 시스템은 CMake(포함된 테스트 드라이버 CTest를 통해)를 사용하여 실행하거나 사용자 정의 Python 드라이버를 사용하여 수동으로 실행할 수 있습니다. 두 시스템 모두 테스트와 관련하여 유사한 기능을 제공하지만 CTest 통합은 CDash를 통해 멀티스레딩, 자동화 및 테스트 보고에 대한 액세스를 제공합니다. 두 실행 모드 모두 다음 섹션에 설명된 대로 일부 구성이 필요합니다.

두 가지 실행 모드 모두에서 다음과 같은 빌드 디렉터리에 디렉터리가 생성됩니다. reg_tests 테스트 사례에 대한 모든 입력 파일이 복사되고(덮어쓰지 않음) 로컬에서 생성된 모든 출력이 저장됩니다. 궁극적으로 CTest와 수동 실행 프로그램은 모두 다음에서 일련의 Python 스크립트와 라이브러리를 호출합니다. reg_tests 및 reg_tests/lib. 그러한 스크립트 중 하나는 lib/pass_fail.py 출력 파일을 읽고 보고된 각 채널의 표준을 계산합니다. 최대 표준이 주어진 허용오차보다 크면 해당 특정 테스트는 실패한 것으로 보고됩니다. 실패 기준은 아래에 설명되어 있습니다.

difference = abs(testData - baselineData)
for i in nChannels:
    if channelRange < 1:
        norm[i] = MaxNorm( difference[:,i] )
    else:
        norm[i] = MaxNorm( difference[:,i] ) / channelRange

if max(norm) < tolerance:
    pass = True
else:
    pass = False

5.2.1. 테스트 환경

우리는 다음을 사용하는 것이 좋습니다 conda 필요한 패키지를 설치하기 위한 로컬 환경을 생성합니다. OpenFAST 테스트. Linux/MacOS 기반 시스템에서 필요한 환경을 설정하기 위한 대략적인 지침으로 다음 프로세스를 사용할 수 있습니다.

  1. 새로 만들기 conda 환경 OpenFAST Python을 테스트하고 설치합니다.

    • conda install python

2. 에서 <openfast>/build 디렉터리에서 다음 명령을 사용하여 환경을 설정합니다.

  • pip install ../requirements.txt

    테스트를 위한 기본 종속성을 설치합니다.

  • pip install -e ../glue-codes/python/.

    다음을 설치합니다. pyOpenFAST 패키지 OpenFAST 저장소

  • pip install -e ../openfast_io/.

    다음을 설치합니다. openfast_io 패키지 OpenFAST 저장소

5.2.2. 종속성

회귀 테스트에는 다음 패키지가 필요합니다(또한 requirements.txt Python 모듈의 루트 디렉터리에 있는 파일):

  • CMake 및 CTest

  • 파이썬 >=3.7

  • 멍청하다

  • vtk

  • 보케>=2.4,!=3.0.0,!=3.0.1,!=3.0.2,!=3.0.3 (선택 사항)

위 패키지 외에도 OpenFAST 저장소가 필요합니다. 우리는 이것을 다음과 같은 곳에 설치하는 것을 권장합니다. conda 시스템 Python 설치를 방해하지 않도록 위 섹션에 설명된 대로 환경을 설정하세요. 사용하여 pip install -e 명령은 시스템 Python 디렉터리 내에 배치하는 대신 로컬 디렉터리를 사용하여 설치합니다.

  • pyOpenFAST Python을 다음의 c-바인딩 라이브러리에 인터페이스하기 위한 패키지입니다. OpenFAST 모듈. 이는 모듈 수준의 일부 테스트에 사용됩니다.

  • openfast_io 읽기와 쓰기를 위한 패키지입니다 OpenFAST 입력 파일. 이는 일부 테스트에서 사용됩니다.

회귀 테스트는 포함된 드라이버를 사용하여 수동으로 실행할 수 있습니다. openfast/reg_tests/manualRegressionTest.py. 이 프로그램은 다음 위치에서 사례 목록 파일을 읽습니다. openfast/reg_tests/r-test/glue-codes/openfast/CaseList.md. 해당 줄을 다음으로 시작하면 사례를 제거하거나 무시할 수 있습니다. #. 드라이버 프로그램에는 help 옵션을 실행하여 얻을 수 있는 여러 선택적 플래그가 포함되어 있습니다.

5.2.4. CTest로 실행

CTest는 CMake에 포함되어 있으며 주로 사전 구성된 대상 및 명령 세트입니다. 회귀 테스트에 CTest 드라이버를 사용하려면 다음 설명에 따라 CMake를 실행합니다. OpenFAST 설치, 그러나 다음 추가 플래그를 사용하면: -DBUILD_TESTING=ON.

회귀 테스트 특정 CMake 변수는 다음과 같습니다.

BUILD_TESTING
CTEST_OPENFAST_EXECUTABLE
CTEST_[MODULE]_EXECUTABLE where [MODULE] is the module name
CTEST_PLOT_ERRORS
CTEST_REGRESSION_TOL

전체 회귀 테스트 스위트에 필요한 일부 추가 리소스가 CMake 프로젝트에 포함되어 있습니다. 특히, 외부 ServoDyn 컨트롤러는 특정 시스템에 맞게 컴파일되어 특정 위치에 배치되어야 합니다. 따라서 다음과 같이 빌드 명령을 실행해야 합니다. install 목표:

# Configure CMake with testing enabled and accept the default
# values for all other test-specific CMake variables
cmake .. -DBUILD_TESTING=ON

# Build and install
make install

참고

REMINDER: 5MW 터빈 테스트 사례의 경우 외부 ServoDyn 컨트롤러를 컴파일하여 적절한 디렉터리에 포함해야 합니다. 그렇지 않으면 모든 5MW 사례가 시작되지 않고 실패합니다. 자세한 내용은 해당 문서에서 확인할 수 있습니다. r-테스트 저장소하지만 이 세 개의 DISCON 컨트롤러가 있어야 한다는 점에 유의하세요.

openfast/build/reg_tests/glue-codes/openfast/5MW_Baseline/ServoData/DISCON.dll
openfast/build/reg_tests/glue-codes/openfast/5MW_Baseline/ServoData/DISCON_ITIBarge.dll
openfast/build/reg_tests/glue-codes/openfast/5MW_Baseline/ServoData/DISCON_OC3Hywind.dll

CMake 구성 및 컴파일 후 다음 명령 중 하나를 실행하여 자동 회귀 테스트를 실행할 수 있습니다. make test 또는 ctest 에서 build 예배 규칙서. 전체 OpenFAST 패키지를 빌드하려는 경우 CMake는 CTest를 구성하여 다음 위치에서 새 바이너리를 찾습니다. openfast/build/glue-codes/openfast/openfast. 그러나 테스트 스위트만 빌드하려는 경우 OpenFAST 바이너리는 다음 아래의 CMake 구성에 지정되어야 합니다. CTEST_OPENFAST_EXECUTABLE 깃발. 해당하는 것도 있습니다 CTEST_[MODULE]_NAME 회귀 테스트에 포함된 각 모듈에 대한 플래그입니다.

CTest로 구동하는 경우 다양한 형태의 명령을 실행하여 회귀 테스트를 실행할 수 있습니다. ctest 빌드 디렉토리에서. 기본 명령은 다음과 같습니다.

# Run the entire regression test
ctest

# Disable actual execution of tests;
# this is helpful in formulating a particular ctest command
ctest -N

# Run the entire regression test with verbose output
ctest -V

# Run tests by name where TestName is a regular expression (regex)
ctest -R [TestName]

# Run all tests with N tests executing in parallel
ctest -j [N]

각 회귀 테스트 케이스에는 사용된 모든 모듈을 연결하는 일련의 레이블이 포함되어 있습니다. 라벨링은 테스트 인스턴스화에서 볼 수 있습니다. reg_tests/CTestList.cmake 또는 다음 명령을 사용하여:

# Print all available test labels
ctest --print-labels

특정 레이블에 해당하는 테스트 케이스는 다음 명령을 사용하여 실행할 수 있습니다.

# Filter the test cases corresponding to a particular label
ctest -L [Label]

플래그는 다음과 같은 유용한 변형을 만들어 합성될 수 있습니다.

# Run all cases that use SubDyn with verbose output
ctest -V -L subdyn

# Run all cases that use SubDyn in 16 concurrent processes
ctest -j 16 -L subdyn

# Run the case with name "5MW_DLL_Potential_WTurb" with verbose output
ctest -V -R 5MW_DLL_Potential_WTurb

# List all tests with the "beamdyn" label
ctest -N -L beamdyn

# List the labels included in all tests matching the regex "bd"
ctest -N -R bd --print-labels

자동화된 회귀 테스트는 빌드 디렉터리에만 새 파일을 씁니다. 특히, 로컬로 생성된 모든 솔루션은 해당 글루 코드 또는 모듈 내의 모듈에 있습니다. openfast/build/reg_tests. 에 포함된 기본 솔루션 openfast/reg_tests/r-test 엄격하게 읽혀지며 자동화된 프로세스에 의해 수정되지 않습니다.

5.2.5. 회귀 테스트 예

다음 예에서는 Unix 기반 시스템에서 회귀 테스트를 실행하는 방법을 보여줍니다. 그러나 CMake 및 CTest를 사용하여 Windows에서도 유사한 절차를 사용할 수 있습니다. Windows에서 회귀 테스트를 실행하는 다른 방법은 다음과 같습니다. Windows에서 실행하는 자세한 예.

5.2.5.1. OpenFAST를 컴파일하고 CTest로 실행

다음 예에서는 사용자가 처음부터 완전히 시작한다고 가정합니다. 아래 명령은 소스 코드를 다운로드하고, CMake로 OpenFAST 프로젝트를 구성하고, 모든 실행 파일을 컴파일하고, 전체 회귀 테스트 모음을 실행합니다.

# Download the source code from GitHub
#    Note: The default branch is 'main'
git clone --recursive https://github.com/openfast/openfast.git
cd openfast

# If necessary, switch to another target branch and update r-test
git checkout dev
git submodule update

# Create the build and install directories and move into build
mkdir build install && cd build

# Configure CMake for testing
# - BUILD_TESTING - turn ON
# - CTEST_OPENFAST_EXECUTABLE - accept the default
# - CTEST_[MODULE]_EXECUTABLE - accept the default
cmake .. -DBUILD_TESTING=ON

# Compile and install
make install

# Execute the full test suite with 4 concurrent processes
ctest -j4

5.2.5.2. CMake 및 특정 실행 파일로 구성

이 예에서는 사용자가 필요한 라이브러리와 함께 사용할 수 있는 모든 기능을 갖춘 OpenFAST 실행 파일을 가지고 있지만 소스 코드 저장소를 다운로드하지 않았다고 가정합니다. 실행 파일이 조직 내에서 배포되거나 다음에서 다운로드되는 경우가 이에 해당할 수 있습니다. OpenFAST 출시. 여기서는 아무것도 컴파일되지 않지만 테스트 스위트는 CTest 명령과 함께 사용하기 위해 CMake로 구성됩니다.

# Download the source code from GitHub
#    Note: The default branch is 'main'
git clone --recursive https://github.com/openfast/openfast.git
cd openfast

# If necessary, switch to another target branch and update r-test
git checkout dev
git submodule update

# Create the build directory and move into it
mkdir build && cd build

# Configure CMake with openfast/reg_tests/CMakeLists.txt for testing
# - BUILD_TESTING - turn ON
# - CTEST_OPENFAST_EXECUTABLE - provide a path
# - CTEST_[MODULE]_EXECUTABLE - provide a path
cmake ../reg_tests \
    -DBUILD_TESTING=ON \
    -DCTEST_OPENFAST_EXECUTABLE=/home/user/Desktop/openfast_executable \
    -DCTEST_BEAMDYN_EXECUTABLE=/home/user/Desktop/beamdyn_driver

# Install required files
make install

# Execute the full test suite with 4 concurrent processes
ctest -j4

5.2.5.3. 특정 실행 파일이 포함된 Python 드라이버

이 예에서는 사용자가 필요한 라이브러리와 함께 사용할 수 있는 모든 기능을 갖춘 OpenFAST 실행 파일을 가지고 있지만 소스 코드 저장소를 다운로드하지 않았다고 가정합니다. 실행 파일이 조직 내에서 배포되거나 다음에서 다운로드되는 경우가 이에 해당할 수 있습니다. OpenFAST 출시. 아무것도 컴파일되지 않지만 포함된 Python 드라이버를 사용하여 테스트 도구 모음이 실행됩니다.

# Download the source code from GitHub
#    Note: The default branch is 'main'
git clone --recursive https://github.com/openfast/openfast.git
cd openfast

# If necessary, switch to another target branch and update r-test
git checkout dev
git submodule update

# Execute the Python driver
cd reg_tests
python manualRegressionTest.py -h
# usage: manualRegressionTest.py [-h] [-p [Plotting-Flag]] [-n [No-Execution]]
#                                [-v [Verbose-Flag]] [-case [Case-Name]] [-module [Module-Name]]
#                                Executable-Name Relative-Tolerance Absolute-Tolerance
#
# Executes OpenFAST or driver and a regression test for a single test case.
#
# positional arguments:
# Executable-Name       path to the executable
# Relative-Tolerance    Relative tolerance to allow the solution to deviate; expressed as order of magnitudes less than baseline.
# Absolute-Tolerance    Absolute tolerance to allow small values to pass; expressed as order of magnitudes less than baseline.
#
# optional arguments:
#   -h, --help            show this help message and exit
#   -p [Plotting-Flag], -plot [Plotting-Flag]
#                         bool to include plots in failed cases
#   -n [No-Execution], -no-exec [No-Execution]
#                         bool to prevent execution of the test cases
#   -v [Verbose-Flag], -verbose [Verbose-Flag]
#                         bool to include verbose system output
#   -case [Case-Name]     single case name to execute
#   -module [Module-Name], -mod [Module-Name]
#                         name of module to execute

python manualRegressionTest.py ..\build\bin\openfast_x64_Double.exe 2.0 1.9

5.2.5.4. Windows에서 실행하는 자세한 예

해당 특정 실행 파일이 포함된 Python 드라이버 예제는 Windows 컴퓨터에서 회귀 테스트를 실행하는 데 사용될 수 있습니다. 그러나 보다 자세한 단계별 설명은 Visual Studio 회귀 테스트를 사용하는 Windows.

5.2.6. 테스트 케이스 추가

모든 실행 모드에서 회귀 테스트는 궁극적으로 다음 위치에 있는 일련의 Python 스크립트에 의해 구동됩니다. openfast/reg_tests 명명 체계가 있는 디렉터리 execute<Module>RegressionTest.py. 새로운 회귀 테스트 케이스를 추가하는 첫 번째 단계는 대상 모듈에 대한 스크립트가 존재하는지 확인하는 것입니다. 그렇지 않은 경우 다음에서 문제를 열어야 합니다. OpenFAST 문제 이 스크립트를 작성하는 데 NLR 팀과 협력합니다.

다음 단계는 테스트 케이스를 적절한 위치에 추가하는 것입니다. r-테스트 서브모듈. r-test의 디렉토리 구조는 OpenFAST의 디렉토리 구조를 미러링하므로 모듈 수준 테스트는 해당 모듈 디렉토리에 배치되어야 하며 글루 코드 테스트는 r-test/glue-codes/openfast. 기존 테스트의 파일 명명 체계를 확인하고 그에 따라 새 테스트 사례 파일을 조정합니다. 특히 기본 입력 파일과 출력 파일 이름은 Python 스크립트의 특정 규칙에 따라 예상될 수 있습니다. 또한 새 테스트 사례에 대한 입력 데크 내의 상대 경로는 r-test 디렉터리 구조 내에서 작동해야 한다는 점을 고려하세요.

테스트 디렉터리가 존재하면 테스트 사례를 적절한 드라이버에 등록해야 합니다. OpenFAST 글루 코드 테스트의 경우 이는 CMake와 독립형 테스트 사례 목록 모두에서 발생합니다. CMake의 경우 파일을 편집합니다. openfast/reg_tests/CTestList.cmake. 해당 파일 하단의 모듈이나 드라이버에 해당하는 섹션에 추가 테스트를 추가해야 합니다. Python 드라이버의 경우 새 테스트 사례를 다음에 추가해야 합니다. openfast/reg_tests/r-test/glue-codes/openfast/CaseList.md. 이 시점에서 CTest 등록을 확인할 수 있습니다.

# Move into the build directory
cd openfast/build

# Run CMake to take the new changes to the test list
cmake .. -DBUILD_TESTING=ON  # If the BUILD_TESTING flag was previously enabled, this can be left off

# List the registered tests, but don't run them
ctest -N

모듈 회귀 테스트의 경우 실행할 수 있는 유일한 옵션은 CMake 드라이버를 사용하는 것이므로 위 지침에 따라 편집하세요. CTestList.cmake.

마지막으로 r-test 하위 모듈의 새 테스트 사례를 r-test 저장소에 추가해야 합니다. 이렇게 하려면 다음에서 새 이슈를 엽니다. r-테스트 문제 테스트를 커밋하기 위해 NLR 팀의 지원을 요청합니다.
