3. OpenFAST 작업

이 섹션에서는 OpenFAST의 일반적인 사용 사례 중 일부에 대한 지원을 제공합니다. 이는 사용자가 사용 가능한 OpenFAST 실행 파일을 가지고 있다고 가정합니다(참조: OpenFAST 설치 설치용).

3.1. 빠른 시작: OpenFAST 실행

이 Quick Start에서는 OpenFAST를 실행하는 방법을 설명합니다. OpenFAST는 일반적으로 터미널(명령 프롬프트 또는 명령줄이라고도 함)에서 실행됩니다. OpenFAST를 실행하는 가장 간단한 방법은 OpenFAST 실행 파일을 작업 디렉터리에 복사한 다음 해당 디렉터리에서 터미널을 여는 것입니다. 따라서 단계는 다음과 같습니다.

  • 시뮬레이션을 실행할 디렉터리에 OpenFAST 실행 파일을 복사합니다.

  • 터미널 열기

  • OpenFAST 실행 파일이 포함된 폴더로 이동합니다.

  • OpenFAST를 실행하여 버전을 확인하세요.

  • 주어진 입력 파일에서 OpenFAST를 실행하십시오.

단계는 아래에 자세히 설명되어 있습니다.

3.1.1. 터미널 열기

특정 운영 체제에서 터미널을 여는 방법을 알아보려면 다음 검색어를 사용해 보세요.

3.1.2. 시뮬레이션 디렉터리로 이동

터미널에서 다음 명령을 사용하여 폴더 간을 탐색할 수 있습니다. CD. 이 예에서는 시뮬레이션 디렉터리가 다음과 같다고 가정합니다. 시뮬레이션/테스트따라서 이 디렉토리로 이동하려면 다음을 입력해야 합니다.

cd simulations
cd test

또는:

cd simulations/test

상위 디렉토리로 이동하려면 다음을 사용할 수 있습니다. CD ... 디렉터리 경로에 공백이 포함되어 있으면 경로 주위에 따옴표를 사용하십시오. 일반적으로 디렉터리 및 파일 이름에 공백을 사용하지 않는 것이 좋습니다. 경로는 절대 경로일 수도 있습니다. 예: CD C:/시뮬레이션/테스트.

3.1.3. OpenFAST를 실행하여 버전 번호를 확인하세요.

터미널이 OpenFAST가 있는 디렉터리에 있으면 OpenFAST를 실행하고 다음과 같이 버전을 확인할 수 있습니다.

./openfast /h

해당 ./ 명령 시작 부분의 문자는 실행 파일이 현재 디렉터리에 있음을 나타냅니다. 위의 명령은 OpenFAST의 버전과 컴파일 옵션을 표시하고 OpenFAST 실행 파일을 호출하기 위한 구문에 대한 도움말 메시지를 표시합니다.

참고

터미널 창에 오류와 경고가 표시되므로 항상 터미널 창에 표시된 OpenFAST의 출력을 읽으십시오. 일반적으로 터미널에 오류가 표시되면 다음에 제공된 지침을 사용할 수 있습니다. 간단한 문제 해결 문제 해결을 위해.

경고

입력 파일 형식은 버전마다 변경될 수 있으므로 사용 중인 OpenFAST 버전을 추적하는 것이 중요합니다. API 버전 간 변경).

팁

작업 디렉터리에 실행 파일을 복사할 필요가 없도록 하려면 실행 파일을 폴더에 배치하고 이 폴더를 시스템 경로에 추가하면 됩니다. 이 방법을 선택하고 터미널을 다시 시작하면 다음을 실행할 수 있습니다. 빠른 속도 /h 어떤 폴더에서든 이번에는 ./ 필요하지 않습니다.

3.1.4. 첫 번째 OpenFAST 시뮬레이션 실행

시뮬레이션을 실행하는 일반적인 구문은 다음과 같습니다.

./openfast InputFile.fst

여기서 InputFile.fst 기본 OpenFAST 입력 파일입니다. 확장 .fst OpenFAST의 기본 입력 파일에 권장됩니다. .dat 다른 입력 파일의 경우. OpenFAST 입력 파일의 입력 파일 형식 사양은 다음과 같습니다. 입력 파일 형식.

첫 번째 OpenFAST 실행을 시작할 수 있도록 최소한의 작업 예제를 제공합니다. 이 예에서는 역사적인 NREL 5-MW 가상이지만 대표적인 다중 MW 풍력 터빈인 풍력 터빈은 정격 출력 5 MW, 정격 로터 속도 12.1rpm, 허브 높이 90m, 로터 직경 126m입니다. 이 예는 타워가 처음에 타워 상단에서 3m 변위된 구조(공기 역학 없음)만 있는 "육지" 버전의 터빈에 대한 것입니다. 파일은 다음 위치에 있습니다. github 디렉토리 . 다음 파일을 다운로드하여 작업 디렉터리에 배치해야 합니다.

./openfast Main.fst

시뮬레이션이 성공적으로 실행되어야 하며 OpenFAST는 확장자를 가진 출력 파일을 생성합니다. .밖으로 또는 .outb. 우리는 간단한 Python 및 Matlab 스크립트를 제공합니다. github 디렉토리 이 시뮬레이션의 일부 출력 채널을 표시합니다. 출력을 시각화하는 방법에 대한 자세한 내용은 다음을 참조하세요. 입력 및 출력 파일 시각화. 일반적으로 터미널에 오류가 표시되면 다음에 제공된 지침을 사용할 수 있습니다. 간단한 문제 해결 문제 해결을 위해.

팁

특정 플랫폼(예: Windows)에서는 입력 파일을 파일 탐색기의 OpenFAST 실행 파일로 끌어다 놓으면 시뮬레이션이 실행됩니다. 이 방법을 사용하면 오류가 발생하면 오류 메시지를 볼 수 없습니다.

팁

OpenFAST 실행 파일과 기본 OpenFAST 입력 파일에 대한 상대 및 절대 경로를 사용할 수 있습니다. OpenFAST의 입력 파일에는 다른 입력 파일을 참조하는 파일 경로도 포함되어 있습니다. 이러한 파일 경로는 현재 파일에 상대적이거나 절대 경로일 수 있습니다.

3.2. 시뮬레이션 문제 해결

3.2.1. 간단한 문제 해결

시뮬레이션 중에 오류가 발생하면 OpenFAST는 다음 종류의 메시지와 함께 중단됩니다.

FAST encountered an error during module initialization.
Simulation error level: FATAL ERROR

Aborting OpenFAST.

이 메시지 위의 줄은 오류의 성격을 나타내며 이 정보는 시뮬레이션 문제를 해결하는 데 사용될 수 있습니다.

3.2.1.1. 일반적인 오류

몇 가지 일반적인 오류와 해결 방법은 다음과 같습니다.

  • 입력 파일 "FILE"를 찾을 수 없습니다: 표시된 대로 입력 파일을 찾을 수 없습니다. Linux 및 Mac 플랫폼은 대소문자를 구분하며 슬래시가 필요합니다. OpenFAST는 상대 또는 절대 경로를 허용합니다. 상대 경로는 참조되는 파일을 기준으로 표현됩니다.

  • VAR를 읽으려고 시도하는 동안 "FILE" 파일에 잘못된 입력이 있습니다.: 이러한 오류는 일반적으로 OpenFAST의 입력 파일 중 하나를 읽을 때 초기화 시 발생합니다. 입력 파일의 변수 유형이 잘못되었을 수 있습니다(논리 대신 정수, 문자열 대신 부동 등). 그러나 매우 자주 이러한 오류는 입력 파일이 실행 중인 OpenFAST 버전에 맞게 형식이 지정되지 않았음을 나타냅니다. 파일이 오래되었을 가능성이 높습니다. OpenFAST 입력 파일에 줄이 추가되는 경우가 많습니다. 당신은 볼 수 있습니다 API 버전 간 변경 OpenFAST 버전 간에 어떤 줄이 변경되었는지 확인하거나 r-테스트 OpenFAST의 최신 릴리스 및 개발 버전에 대한 입력 파일의 작업 예를 찾으십시오.

  • “FILE”의 데이터를 구문 분석하는 중에 치명적인 오류가 발생했습니다. #II 줄에서 변수 “VAR”를 찾을 수 없습니다.. 이러한 오류는 위에서 설명한 오류와 유사합니다. 파일이 사용 중인 OpenFAST 버전에 적합한 형식인지 확인하세요.

유사한 메시지는 사용자 입력 오류를 나타냅니다(선택한 옵션을 사용할 수 없거나 호환되지 않는 경우). 이러한 오류 메시지는 일반적으로 충분히 명시적입니다. 몇 가지 지침은 입력 파일의 주석을 살펴보고 각 모듈의 개별 입력에 대한 자세한 내용은 사용자 가이드를 참조하세요. 사용자 문서.

팁

90%의 경우 오류는 OpenFAST 버전과 입력 파일 간의 불일치로 인해 발생합니다(위의 두 번째 항목 참조).

3.2.1.2. 일반적인 경고

일부 경고는 때때로 다른 모듈(일반적으로 공기 역학 모듈)에서 발생하여 명령 창에 보고될 수 있습니다.

  • SkewedWakeCorrection에서 큰 카이 값이 발생했습니다.: 터빈의 요잉/타이틀이 매우 높음을 나타냅니다. 터빈이 중요한 동작을 할 때 발생할 수 있습니다.

  • 낮은 TSR로 인해 BEM 솔루션이 꺼지고 있습니다.: 순간 로터 속도가 0에 가깝거나 상대 풍속이 크다는 것을 나타냅니다(출력 확인) RtSpeed 및 RtVavgx).

경고는 때때로 무시될 수 있지만 모델에 문제가 있음을 나타내는 경우가 많습니다. 고급 문제 해결의 다음 섹션을 참조하세요.

3.2.2. 고급 문제 해결

어떤 경우에는 시뮬레이션 중에 시뮬레이션이 중단될 수 있습니다(FAST에서 시뮬레이션 시간 T에 오류가 발생했습니다.) 또는 실행되지만 몇 가지 시간 단계(최소 1시간 단계) 후에 비어 있거나 "NaN" 출력이 있을 수 있습니다. 이러한 오류는 일반적으로 모델이 비물리적이기 때문에 발생합니다. 이러한 경우 명령 창에 다음과 같은 종류의 오류 메시지가 표시될 수 있습니다.

  • 작은 각도 가정이 위반되었습니다. 또는 GetSmllRotAngs()의 각도가 0.4 라디안보다 큽니다.: 이러한 경고는 구조의 일부가 큰 회전을 겪고 있음을 나타내는 반면 OpenFAST의 일부 모듈은 작은 각도 근사치에서만 유효합니다.

  • GetSmllRotAngs()에서 분모는 0입니다.

일반적으로 시뮬레이션이 중단되거나 비현실적인 값 또는 NaN 값이 있는 경우 모델에 오류가 있을 가능성이 있습니다(구조가 너무 뻣뻣하거나, 너무 부드럽거나, 유입이 올바르지 않거나, 초기 조건이 올바르지 않거나, 컨트롤러가 예기치 않게 작동하거나, OLAF 정규화 매개변수가 잘못 설정됨 등).

팁

문제 해결의 핵심은 모델을 단순화하는 것입니다. 모델이 실행되어 물리적 결과를 생성할 때까지 모델을 점진적으로 단순화하도록 선택할 수 있습니다. 또는 그 반대로 모델을 최대한 단순화하고 점진적으로 복잡성을 다시 도입하세요. 일반적인 단순화에는 공기 역학 없음, 견고한 구조, 안정적인 유입, 컨트롤러 없음이 포함됩니다.

다음은 모델 문제를 해결하기 위해 취할 수 있는 몇 가지 단계입니다. 특히 문제를 특정 모듈로 분리한 다음 입력하려고 시도합니다.

  • 단순한 환경 조건(꾸준하고 균일한 유입, 정수)을 사용하여 모델을 단순화합니다.

  • 컨트롤러 제거: GenDOF ElastoDyn에서 False로 설정하고 CompServo 기본 입력 파일에서 0으로 설정합니다. 로터는 일정한 RPM로 회전합니다.

  • ElastoDyn 입력 파일에서 대부분의 자유도를 꺼서 모델을 단순화하십시오. 모든 자유도를 유지하고 점진적으로 더 많은 자유도를 추가하는 것부터 시작할 수 있습니다. 이는 문제가 블레이드, 나셀, 타워 또는 하부 구조에서 발생하는지 여부를 나타낼 수 있습니다. 종종 문제가 되는 일부 자유도는 드라이브 트레인 비틀림(DrTrDOF) 및 요 자유도(YawDOF). ElastoDyn의 드라이브 트레인 강성과 댐핑 값은 종종 잘못 설정됩니다. Yaw의 일반적인 문제는 다음과 같습니다. NacYaw (ElastoDyn에서) 및 YawNeut (ServoDyn에서) 불일치하거나 요 스프링과 댐핑이 YawSpr 및 YawDamp 육체적이지 않습니다. 해양 시뮬레이션의 경우 YawDOF 및 PtfmYDOF 켜져 있으면 모델에 현실감이 있어야 합니다. PtfmYIner 그렇지 않으면 이러한 자유도는 ElastoDyn에서 잘못 정의됩니다. PtfmYiner에는 편향되지 않은 타워의 회전 관성이 포함되어야 하며, SubDyn를 사용하지 않는 경우 플랫폼/TP(있는 경우)의 비틀림 관성이 포함되어야 합니다.

  • 물리적 모델 단순화: ElastoDyn(CompElast=1) BeamDyn 이상에서는 BEM(WakeMod=1) OLAF 이상에서는 SubDyn에서 0 Craig-Bampton 모드를 사용합니다.

  • 시계열 출력을 시각화합니다(참조: 입력 및 출력 파일 시각화). 모델에 관련 변위 출력을 추가하세요(예: PtfmSurge, PtfmSway, PtfmHeave, PtfmRoll, PtfmPitch, PtfmYaw, NacYaw, TTDspFA, TTDspSS, RotSpeed, OoPDefl1, IPDefl1 및). RtSkew. 모델의 일부 오류로 인해 터빈에 큰 변위가 있을 가능성이 있습니다.

  • 초기 조건을 조정하세요. 위에서 언급했듯이, NacYaw (ElastoDyn) 및 YawNeut (ServoDyn)는 요 자유도가 켜져 있을 때 일치해야 합니다. 구조가 환경 조건을 고려할 때 비현실적인 초기 위치에 있는 경우 초과될 가능성이 있습니다(예: 풍속은 높지만 피치가 너무 낮음). 일반적인 오류는 시뮬레이션의 초기 풍속에서 로터 속도와 블레이드 피치 각도를 예상(평균) 값으로 초기화하지 않는 것이며, 이는 많은 풍력 터빈 컨트롤러에 문제를 일으킵니다.

  • 입력을 시각화합니다(참조: 입력 및 출력 파일 시각화). 블레이드와 타워의 질량 및 강성 분포가 예상한 것과 같은지 확인합니다.

  • 시스템의 질량과 강성을 확인하십시오. 블레이드 질량과 타워 상단 질량은 ElastoDyn 요약 파일에 표시됩니다. 하위 구조의 해당 6x6 행렬은 SubDyn 요약 파일에서 찾을 수 있습니다.

  • 문제를 특정 모듈로 분리한 경우 이 모듈의 요약 파일에 제공된 정보를 확인하세요. 대부분의 모듈에는 입력 파일 끝에 다음과 같은 플래그가 있습니다. SumPrint 또는 유사하게 요약 파일이 디스크에 기록됩니다.

  • 시간 단계를 줄입니다. 시뮬레이션 시간 단계는 시스템에서 모델링된 주파수를 기반으로 조정되어야 합니다. 일반적으로 시간 단계는 가장 빠른 주파수의 약 1/10에 있어야 합니다. BeamDyn 및 SubDyn와 같은 모듈에는 일반적으로 미세한 시간 단계가 필요합니다. 시간 단계를 줄이는 대신 1개의 수정 단계를 도입하는 것과 동일한 경우가 많습니다(NumCrctn). 수정이 사용되는 경우 야코비안은 정기적으로 업데이트되어야 합니다(예: 설정). DT_UJac 최대 100개의 시간 단계. 플로팅 시스템의 경우 다음을 사용하는 것이 좋습니다. DT_UJac = 1/(10*f_pitch), 어디 f_pitch 는 플로팅 풍력 터빈의 고유 진동수(피치)입니다.

  • 진공 상태에서 구조의 선형화를 수행합니다(CompInflow=0, CompAero=0) 및 정지 상태(RotSpeed=0) (보다 선형화 해석 수행) 주파수와 감쇠가 예상 범위 내에 있는지 확인하십시오. 그렇지 않으면 구조적 입력을 조정하십시오.

  • OpenFAST에서 사용하는 터빈 및 다양한 메시의 시각화를 위해 VTK 출력을 생성합니다. VTK 출력은 다음을 사용하여 활성화됩니다. WrVTK=1 또는 WrVTK=2. VTK는 폴더에 기록됩니다. vtk* 기본 디렉토리에 있으며 Paraview를 사용하여 시각화할 수 있습니다(참조 입력 및 출력 파일 시각화).

3.7. 선형화 해석 수행

3.7.1. 배경

많은 응용 프로그램에는 고유값 분석, 주파수 영역 분석, 관찰자를 위한 선형 상태 공간 모델 등 시스템의 선형 모델이 필요합니다. OpenFAST의 대부분 모델은 비선형이므로 기본 시스템의 선형화가 필요합니다. Linearization는 시스템의 상태 및 입력 값 세트(일반적으로 시뮬레이션의 주어진 시간)에 해당하는 특정 작동 지점에 대해 수행됩니다. 선형화의 출력은 작동 지점 부근에서 유효한 선형 상태 공간 모델(상태, 입력 및 출력과 관련된 4개의 행렬)입니다.

로터가 회전하기 때문에 평형 솔루션이 존재한다면 주기적일 가능성이 높습니다. 회전 기간 동안 다양한 작동 지점(즉, 다양한 방위각 위치)에서 선형화해야 합니다.

추가적인 복잡성은 OpenFAST의 상태 중 일부가 회전 기준 프레임에 있다는 것입니다(예: ElastoDyn 블레이드 상태). 고정된(비회전) 참조 프레임에 있는 시스템의 선형 상태 공간 모델을 얻으려면 다중 블레이드 좌표 변환(MBC)이 적용됩니다. 순수 주기 시스템의 경우, MBC는 서로 다른 방위각 위치의 선형화된 출력에 적용할 수 있으며, 이를 결합하여 고정 기준 프레임에서 선형화된 시스템을 형성할 수 있습니다. MBC는 3개 이상의 블레이드에만 적용됩니다. Floquet 이론에는 1개 또는 2개의 블레이드가 필요하지만 NLR에는 현재 Floquet 이론을 사용하는 후처리 프로세서가 없습니다.

참고

현재 권장되는 방법은 주기성을 피하고 평형이 일정하도록 모델을 단순화하는 것입니다(예: 기울기 및 중력 제거). MBC는 여전히 필요하지만 다른 방위각 위치에서 다른 선형화를 사용할 필요는 없습니다.

선형화의 출력 중 하나는 상태 행렬(A) 시스템 상태를 시간 파생물과 연관시킵니다. 고유값 분석 A 전체 시스템 모드 형태와 해당 주파수 및 감쇠를 제공합니다.

참고

선형 유한 요소 소프트웨어와 달리 OpenFAST에는 전체 시스템 강성 및 질량 행렬 개념이 없습니다(일부 모듈에는 로컬 행렬이 있지만 모듈과만 관련됨). 기본 방정식 시스템은 비선형이며 시스템의 주파수는 작동 조건(예: 풍속, 회전 속도)에 따라 달라집니다.

아래 섹션에서는 OpenFAST를 사용하여 선형 모델을 얻는 프로세스를 자세히 설명하고 시스템 모드의 주파수 및 감쇠를 얻기 위한 적용에 중점을 둡니다.

3.7.2. 단일 시뮬레이션에 대한 선형화된 모델(수동)

이 섹션에서는 OpenFAST를 사용하여 시스템의 선형화된 모델을 생성하는 주요 단계를 설명합니다.

간단한 선형화 분석을 수행하는 단계는 다음과 같습니다.

  1. 메인 편집 .fst 파일, 설정 Linearize=참

  2. 출력 형식 설정 OutFmt "ES20.11E3"으로. 출력 파일은 정확한 고유값 분석에 필요한 고해상도로 작성됩니다.

경고

선형화 출력 파일은 ASCII 형식이므로 고유값 분석 결과는 출력 해상도(OutFmt). 따라서 위에서 언급한 것처럼 이 매개변수를 큰 정밀도로 설정하는 것이 중요합니다.

  1. 선형화가 수행되는 시점을 결정하는 두 가지 주요 방법이 있습니다.

    • 사용하여 CalcSteady=거짓, 사용자는 다음을 사용하여 선형화가 발생하는 시간을 규정합니다. NLinTimes 및 LinTimes (시스템이 평형 상태에 있거나 주기적인 정상 상태에 있는 시간, 즉 충분히 긴 시간을 제공하는 것은 사용자의 책임입니다.) - CalcSteady=참 (권장 접근 방식) OpenFAST는 시스템이 주기적인 정상 상태에 있을 때(주어진 허용 오차에 따라) 자동으로 선형화를 시작합니다. TrimTol) 그리고 수행할 것입니다 NLinTimes 로터 회전에 대한 선형화. 컨트롤러를 사용하는 경우 옵션 CalcSteady 또한 입력에 따라 컨트롤러 입력(피치, 요 또는 생성기 토크)을 조정합니다. TrimCase) 초기 조건에 표시된 회전 속도에 도달하는 것과 같습니다. 그만큼 TrimGain 및 TrimTol 조정이 필요할 수도 있습니다. Twr_Kdmp 및 Bld_Kdmp 정상 상태 계산 중에 타워와 블레이드에 감쇠를 추가하는 데 사용할 수 있습니다. 이는 정상 상태 계산 속도를 높이는 데 도움이 될 수 있으며 타워 및/또는 블레이드가 불안정한 경우 필요할 수 있습니다. 일단 정상상태 해를 찾았습니다. Twr_Kdmp 및 Bld_Kdmp 선형화 결과에 영향을 미치지 않습니다(즉, 선형 솔루션에는 추가 타워 및 블레이드 댐핑이 없습니다).

  2. 선형화 수를 선택했습니다. 정지상태의 경우, NLinTimes=1, 회전하는 경우 평형점이 주기적이면 사용하는 것이 좋습니다. NLinTimes=36 (방위각 회전 10도마다 선형화에 해당), 그렇지 않은 경우 NLinTimes=1. 만약에 CalcSteady=거짓 그리고 사용자가 설정한 NLinTimes=36, 사용자가 설정해야 합니다. LinTimes 회전자 속도에 기초한 고유한 방위각 위치에 있는 회전자에 해당하는 값을 갖습니다.

  3. 일반적인 선형화의 경우 사용자는 다음을 설정할 수 있습니다. LinInputs=0, LinOutputs=0, LinOutJac=거짓, LinOutMod=거짓, Twr_Kdmp=0, Bld_Kdmp=0 (OpenFAST 입력 파일 문서 참조) 환경 LinInputs = LinOutputs = 0 B, C, D 행렬 생성을 방지합니다(입력 및 출력 없음). 선형화 시스템에 내재된 표준 선형화 입력 세트는 다음과 같은 경우에 사용할 수 있습니다. LinInputs=1. 여기에는 다음이 포함됩니다. 집단 블레이드 피치. 와 함께 LinOutputs = 1, 의 출력은 OutList 각 모듈의 섹션은 선형화된 시스템에 포함됩니다. 예를 들어, GenSpeed 포함하여 포함될 수 있습니다. GenSpeed 다음 내의 OutList ElastoDyn의. OpenFAST 세트의 모든 입력 및 출력에 대한 Linearization LinInputs=2, LinOutputs=2, 큰 출력 파일을 갖는 대신.

  4. 이것에 대해 OpenFAST를 실행하십시오. .fst 파일. OpenFAST는 각각의 개별 선형화를 수행할 때 메시지를 표시하며, 개별 파일은 .lin 확장 프로그램이 디스크에 기록됩니다.

  5. 일반 출력 파일을 확인하는 것이 좋습니다 .밖으로 또는 .outb. 만약에 CalcSteady=거짓, 사용자는 선형화가 실행되는 시점에 터빈이 실제로 정상 상태(또는 주기적인 정상 상태)에 도달했는지 확인해야 합니다. 만약에 CalcSteady=참 컨트롤러를 사용하면 사용자는 회전 속도가 실제로 원하는 RPM에 수렴되었는지 확인할 수 있으며 잠재적으로 조정을 선택할 수 있습니다. TrimGain 및 TrimTol 향후 실행을 위해.

선형화 파일 *.lin 그런 다음 제공된 Python 또는 MATLAB 도구를 사용하여 후처리됩니다.

참고

선형화를 수행할 때 OpenFAST의 모든 모듈과 옵션을 사용할 수 있는 것은 아닙니다. OpenFAST는 사용 가능한 옵션을 나타내는 오류 메시지와 함께 중단됩니다. 이에 따라 입력 파일을 조정하십시오.

3.7.3. 후처리

시스템의 고유 주파수를 얻기 위해 사용자는 다음을 열 수 있습니다. .lin 파일에서 상태 매트릭스를 추출합니다. A 고유값 분석을 수행합니다. 회전하는 로터의 경우 다양한 방위각 위치에서 시뮬레이션을 통해 생성된 모든 lin 파일을 열고 MBC 변환을 사용하여 변환해야 합니다. 이러한 경우를 위한 스크립트를 제공합니다.

단 하나의 선형화 파일만 사용되는 경우(예: 정지 상태) 스크립트는 postproLin_OneLinFile_NoRotation 사용할 수 있습니다. 다음에서 발견됩니다. matlab-toolbox/Campbell/예제 또는 openfast_toolbox/openfast_toolbox/선형화/예제/.

여러 선형화 파일을 후처리해야 하는 경우(특히 다른 방위각 위치에 해당하는 여러 파일) ​​스크립트는 postproLin_MultiLinFile_Campbel 위에서 언급한 것과 동일한 폴더에 위치하여 사용할 수 있습니다. 다른 풍속과 RPM(다른 OpenFAST 호출을 통해)에서 선형화가 수행된 경우에도 스크립트를 사용할 수 있습니다. 이러한 다양한 풍력 터빈 작동 조건에서 주파수와 감쇠를 표시하는 것을 캠벨 다이어그램이라고 합니다.

3.7.4. 캠벨 다이어그램

가까운 시일 내에 Campbell 다이어그램 생성 프로세스를 단순화하기 위한 전용 도구가 제공될 예정입니다.

그때까지는 다양한 풍력 터빈 작동 조건에 대한 입력 파일을 수동으로 편집하는 프로세스를 피하기 위해 우리는 스크립트를 제공합니다. runCampbell,에서 발견됨 matlab-toolbox/Campbell/예제 또는 openfast_toolbox/openfast_toolbox/선형화/예제/. 스크립트는 참조 "fst" 파일인 템플릿 폴더에 의존합니다. 폴더를 복제하고, 풍력터빈 운전조건(풍속/rpm)별 파일을 생성한 후, OpenFAST를 실행하고 선형화 파일을 후처리한다.

스크립트 runCampbell CSV 파일 세트 또는 Excel 파일을 생성합니다. 스크립트는 모드(예: 첫 번째 타워 앞뒤 모드, 첫 번째 플랩 모드 등)를 식별하려고 시도하지만 모드를 완전히 식별하려면 일반적으로 수동 프로세스가 필요합니다. 이 과정은 어렵고 지루할 수 있습니다. 시스템에 익숙해지려면 먼저 진공 상태에서 작동 지점이 거의 없는 시뮬레이션을 진행하는 것이 좋습니다.

수동 식별 프로세스는 CSV 파일을 변경하는 것으로 구성됩니다. Campbell_ModesID.csv (또는 Excel 스프레드시트 ModesID Excel 출력을 사용하는 경우). 재실행 시 이 파일을 다시 작성하지 않으려면 runCampbell, 이 파일의 이름을 다음과 같이 바꾸는 것이 좋습니다. Campbell_ModesID_Manual.csv. 스크립트의 일부 runCampbell 캠벨 다이어그램을 플롯하는 것은 "수동" 파일을 사용하도록 조정할 수 있습니다. Python 및 MacOS와 호환되는 방식이므로 CSV 형식을 사용하는 것이 좋습니다.

수동 식별 프로세스는 모드 테이블의 속성 인덱스로 구성되며, 여기서 인덱스는 정렬된 모드 빈도 목록에 해당합니다.

예를 들어, CSV 파일을 엑셀로 열면, ModeID 파일은 다음과 같습니다.

Mode Number Table
Wind Speed (mps)   2.0   5.0   8.0
1st Tower FA        0     0     0
1st Tower SS        1     0     0

이 예에서는 선형화가 2, 5, 8m/s로 실행되었다고 가정합니다. 표의 "0"은 모드가 식별되지 않았음을 나타냅니다. 파일을 보시면 됩니다 Campbell_Summary.txt 각 모드 및 작동 지점에 대한 주파수, 감쇠 및 "모달 콘텐츠"를 살펴보십시오. 자세한 내용을 보려면 각 작동 지점에 대한 개별 CSV 파일을 열 수 있습니다. (Excel 형식을 사용한 경우에는 다른 시트에 있습니다.) 2m/s와 5m/s의 경우 타워 앞뒤가 두 번째 주파수이고 타워 측면이 모드 목록에 나타나는 첫 번째 주파수라는 것을 알 수 있습니다. 8m/s에서는 반대 현상이 발생하는 것을 발견할 수 있습니다. 이 경우 다음과 같이 파일을 편집합니다.

Mode Number Table
Wind Speed (mps)   2.0   5.0   8.0
1st Tower FA        2     2     1
1st Tower SS        1     1     2

주요 질문은 어떤 모드가 어떤 모드인지 결정하는 방법입니다. 이 질문에 대한 진정한 해결책은 없습니다. 식별에 도움이 되는 몇 가지 요소는 다음과 같습니다.

  • 시스템 주파수는 일반적으로 0m/s 및 0rpm에서 쉽게 결정됩니다. 시스템 주파수는 RPM/WS/피치가 변경됨에 따라 이 기준점에서 점진적으로 변경됩니다. 블레이드 회귀 및 프로그레시브 모드는 일반적으로 회전 속도가 증가함에 따라 회전 속도 주파수 +/-와 동일한 "분할"을 표시합니다. 플랩의 집단 모드는 원심력 강화로 인해 로터 속도에 따라 주파수가 증가하는 경향이 있습니다.

  • 블레이드 플랩 모드는 공기 역학이 존재할 때 일반적으로 감쇠가 매우 높습니다(가장자리 방향 모드보다 훨씬 더 댐핑됨).

  • 작동 지점에서 다음 지점까지 감쇠는 크게 변하지 않습니다.

  • 타워 모드는 작동 조건 변화에 큰 영향을 받지 않습니다.

  • 각 모드의 에너지가 어디에 있는지 확인하려면 "모드 콘텐츠"를 살펴봐야 합니다. 파일 Campbell_Summary.csv 모드 내용의 요약을 표시합니다. 어떤 경우에는 명확한 최대값이 없습니다(키워드 NoMax 표시됩니다). 이 경우 모드를 식별하는 것이 어려울 수 있습니다. 개별 작동 지점 파일에서도 유사한 내용을 찾을 수 있습니다.

  • 모드를 시각화하면 모드를 식별하는 데 도움이 될 수 있습니다(다음 섹션 참조). 이 과정은 아직 시간이 오래 걸릴 수 있습니다.

식별 테이블이 설정되면. 파일을 저장하고 캠벨 다이어그램을 플로팅합니다. 만족스러운 다이어그램을 얻을 때까지 프로세스가 반복될 수 있습니다. 이 과정에서 Excel을 닫을 필요는 없습니다.

우리는 프로세스가 길다는 것을 알고 있습니다. 이 프로세스를 간소화하기 위해 노력하는 동안 양해해 주셔서 감사합니다.
