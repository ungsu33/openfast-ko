OpenFAST 문서 상세 리뷰

검토 기준은 사용자가 지정한 main 문서입니다. 표지의 버전은 v5.0.0, 문서 날짜는 2026년 3월 12일이며, 대응하는 공식 소스 커밋은 2895884d2be01862173c88d70f86b358d2f1a50a입니다. 수집·번역 기준일은 2026년 11월 8일입니다. dev 또는 과거 릴리스의 설명을 임의로 섞지 않았습니다.

검토의 성격

검색 색인에 등록된 158개 문서 전체를 수집하여 구조·링크·수식·코드·표·그림의 보존을 자동 대조했습니다. 아래 기술 리뷰는 주요 사용 경로와 모듈별 핵심 설명·제약을 읽고 해석한 내용입니다. 158개 문장 전체에 대한 전문 번역자의 감수나 OpenFAST 실행·수치 검증을 완료했다는 뜻은 아닙니다. 문서별 구성과 주의문은 전체 검토 목록에서 확인할 수 있습니다.

1. 문서의 전체 구조와 읽는 순서

이 문서는 단일 입문서보다 설치 안내, 실무 사용법, 모듈별 사용자·이론 설명서, 개발 규약을 모은 참조 체계에 가깝습니다. 목차의 깊이가 깊고 모듈별 완성도가 다르므로, 처음부터 순서대로 읽는 것보다 자신의 모델에 필요한 모듈을 먼저 식별하는 편이 효율적입니다.

2. 설치와 첫 실행: 재현성을 좌우하는 부분

설치 장은 사전 빌드 실행 파일과 직접 컴파일 경로를 모두 설명합니다. 사용 목적이 기존 모델 실행이라면 바이너리 또는 컨테이너로 시작할 수 있습니다. 반대로 사용자 정의 풍장, 외부 솔버 연동, 디버깅 또는 새 모듈 개발에는 컴파일러·의존 라이브러리·CMake 설정을 통제하는 소스 빌드가 필요합니다.

  • 버전과 입력 파일의 짝: 실행 파일 버전, 모델 출처, 입력 형식이 맞아야 합니다. 원문 문제 해결 절은 버전 불일치를 빈번한 오류 원인으로 강조합니다.
  • 런타임 의존성: 설치 장은 사전 빌드 바이너리에 Intel Fortran 또는 MKL 재배포 라이브러리가 별도로 필요할 수 있다고 명시합니다. 실행 파일 하나만 복사한 환경에서 동작하지 않는 원인이 될 수 있습니다.
  • 하위 모듈: 회귀 시험 자료는 저장소의 하위 모듈과 연결됩니다. git submodule update --init --recursive 등의 원문 절차를 빠뜨리면 코드만 있고 시험 입력은 없는 상태가 됩니다.
  • 외부 제어기: 5 MW 회귀 사례는 해당 DISCON 제어기 라이브러리가 필요합니다. 누락되면 해석을 시작하기 전에 실패할 수 있습니다. 근거: 회귀 테스트 주의문.
  • WSL 안내의 범위: WSL·VS Code 안내에는 Python 환경과 노트북 사용까지 포함됩니다. texlive-full의 큰 설치 용량에 관한 경고도 있습니다. 모든 실행에 필요한 최소 설치 목록으로 오해하지 않아야 합니다.

검토자 제안: 프로젝트마다 실행 파일 버전과 커밋, 컴파일 옵션, 모델 커밋, 제어기 DLL, 풍장·파랑 시드, 후처리 도구 버전을 함께 기록하면 재현 문제가 줄어듭니다. 이는 문서 내용을 바탕으로 한 관리 제안이며 여기서 시뮬레이션을 실행한 결과는 아닙니다.

3. 입력 파일과 연성 프레임워크

입력 파일은 일반적인 설정 사전이 아닙니다

입력 파일 형식은 첫 값만 읽는 기존 value-column 형식과 key+value 형식을 구분합니다. 두 방식 모두 기본적으로 줄 위치를 전제로 하는 부분이 있으므로, 임의로 순서를 바꾸거나 주석에 남긴 값을 유효한 입력으로 간주하면 오류가 생길 수 있습니다. 번역 사이트에서는 설명을 번역하되 실제 입력 예제와 키워드를 번역하지 않았습니다.

글루 코드가 물리 모듈을 연결합니다

글루 코드는 초기화, 데이터 전달, 시간 적분과 선택적 선형화를 조율합니다. ModVar는 변수와 속성, ModGlue는 전역 배열과 모듈 조합을 다룹니다. 모듈의 입력·출력·상태, 좌표계와 메시 매핑을 구분하는 것이 전체 문서를 이해하는 데 중요합니다.

솔버 설명은 느슨한 연성과 강한 연성, 일반화 알파 적분, Newton 반복, Jacobian 갱신·스케일링 및 수렴 판정을 설명합니다. DT, ModCoupling, ConvTol, DT_UJac 등은 정확도·안정성과 계산비용에 영향을 줍니다. 원문이 제시하는 전형값은 해당 모델에서 검증된 보편적 설정값으로 받아들이지 않는 편이 좋습니다.

검토자 해석: 시간 간격이나 수렴 허용오차를 조정해 프로그램을 종료 없이 실행하는 것만으로 결과의 정확도가 입증되지는 않습니다. 응답의 시간 간격 수렴성, 수렴 경고, 하중·변위 전달과 모델의 물리적 가정을 함께 확인해야 합니다.

4. 공력·후류·소음 모듈

AeroDyn

AeroDyn은 공력 계산의 중심이며 입력 파일, 좌표계, 출력, BEM, 비정상 공력, 꼬리날개, 드라이버와 모델링 지침을 포함합니다. 입력 설명은 v4 이후 입력 체계의 중요한 변경을 안내합니다. 예를 들어 예전 WakeMod와 현재 Wake_Mod, DBEMT_Mod를 같은 의미로 읽으면 안 됩니다.

모델링 절은 로터 회전당 최소 200개의 방위각 시간 단계와 블레이드·타워의 해석 절점 수 10–20개를 초기 지침으로 제시합니다. 동시에 전체 연성 계산에서 더 작은 시간 간격이 필요할 수 있다고 명시합니다. 이는 수렴성 검토를 대신하는 확정값이 아닙니다.

원문 내부에서 발견한 주의점

모델링 절에는 AFAeroMod, SkewMod와 같은 과거 입력명으로 된 설명이 남아 있지만, 입력 파일 절은 새로운 옵션 이름과 대응 관계를 설명합니다. 번역에서 이를 조용히 최신 내용으로 바꾸지 않았습니다. 실제 설정은 사용 중인 실행 파일 버전의 입력 설명·변경 기록과 대조해야 합니다.

BEM_Mod에 따라 일부 출력의 좌표계가 달라질 수 있다는 경고도 중요합니다. 출력 열의 이름만 일치한다고 서로 다른 설정의 하중·유도계수·유입각을 바로 비교하면 해석이 달라질 수 있습니다.

OLAF

OLAF는 AeroDyn의 자유 와류 후류 모델입니다. 입력·출력, 후류 이론, 상태공간 표현, 실행 지침, 순환 지정과 출력 채널 부록을 포함합니다. 실행 지침은 OpenMP 빌드 선택과 계산 지침을 제공합니다. BEM과 다른 해상도·시간 적분·후류 모델 설정을 요구하므로, 동일한 입력 자원으로 계산비용과 정확도를 직접 등치할 수는 없습니다.

공력소음

공력소음 문서는 난류 유입, 난류 경계층–뒷전, 층류 경계층–와류 방출, 팁 와류, 뒷전 두께에 의한 소음과 지향성 모델을 설명합니다. 이론 외에 모델 검증 장이 있어 코드 간 비교와 사례의 조건을 함께 읽을 수 있습니다. 특정 기준 터빈·시험 조건에서의 비교를 모든 형상·운전 조건에서의 성능 보증으로 확대하면 안 됩니다.

AeroDisk

AeroDisk의 개요는 짧고 입출력 설명으로 연결됩니다. 로터의 공력 표현 수준이 AeroDyn과 다르므로 모듈 선택은 필요한 응답과 입력 자료 수준을 기준으로 판단해야 합니다.

5. 구조 모듈과 좌표계

ElastoDyn·BeamDyn·단순화 ElastoDyn

ElastoDyn은 구조동역학의 기본 경로이며 좌표계·입력·이론·절점 출력을 제공합니다. BeamDyn은 기하학적으로 정확한 보 이론과 스펙트럴 유한요소를 설명하며, 큰 변위·회전 및 굽힘·전단·비틀림 등의 연성을 다룹니다. 단면의 6×6 질량·강성 행렬을 어떤 기준축과 순서로 정의했는지가 중요합니다.

BeamDyn 문서에는 전역, 내부 BD, 블레이드 기준, 국부 단면 좌표계가 구분되어 있습니다. 축 이름이 다르거나 블레이드가 변형·회전하면 같은 숫자 배열도 다른 물리량이 됩니다. 단면 특성과 후처리 결과를 가져올 때 해당 표와 정의를 먼저 확인해야 합니다.

단순화 ElastoDyn은 가정과 자유도 범위를 명시한 별도 모델입니다. 검토자 관점에서 모델 단순화는 개발·초기 점검에 유용하지만, 제거된 자유도가 필요한 응답을 이 모델로 평가할 수 있다고 해석해서는 안 됩니다.

SubDyn

SubDyn 문서는 부재·절점 정의, 출력, 정식화, 축약, 모델링 지침과 예제 부록이 풍부합니다. 모델링 지침은 요소 분할, 기초 유연성, 부재 중첩, 타워·하부구조 연결, 자중, Craig–Bampton 축약과 시간 간격을 다룹니다.

SubDyn과 HydroDyn은 서로 다른 메시를 사용할 수 있지만 일관된 형상이 권장됩니다. 원문이 제시하는 수면 근처 해상도와 요소 길이 비율은 시작점이며 구조별 보완이 필요하다고 명시합니다. 수치 축약 모드 수를 줄일 때는 관심 주파수 대역과 응답이 유지되는지 확인해야 합니다.

ExtPtfm

ExtPtfm은 외부에서 제공된 축약 구조모델과의 연결을 다룹니다. 사용법·입력·이론·예제가 함께 있습니다. 외부 모델을 연결할 때 행렬의 자유도 순서, 단위, 기준점과 하중·운동의 정의를 일치시키는 작업이 핵심입니다.

6. 해양 환경·수력·계류

HydroDyn과 SeaState를 함께 읽어야 합니다

HydroDyn은 고정식·부유식 해상 하부구조의 시간 영역 수력을 다루며, SeaState는 HydroDyn이 사용하는 파랑장 정보를 생성합니다. SeaState가 예전에 HydroDyn의 일부였다는 설명이 있어, 기존 자료의 용어·입력 위치와 현재 구성 사이의 차이를 이해하는 데 도움이 됩니다.

HydroDyn 모델링 지침은 파랑, 스트립 이론 분할, 분포·집중 하중, 계수, 운동의 영향, 부가 강성·감쇠, 고정식·부유식 초기 조건과 복원력을 다룹니다. 포텐셜 유동과 스트립 이론을 조합하는 경우에는 부력·복원·관성·감쇠를 중복 반영하지 않도록 각각의 기여를 확인해야 합니다.

원문 기반 주의점: 해당 모델링 절은 내부 파랑 생성의 이론 차수와 파 운동학 계산 영역을 설명합니다. 파랑 이론의 한계, 자유수면·정수면 기준, 물체 운동, 해저 경계와 수심을 적용 조건과 함께 읽어야 합니다. 입력을 채웠다고 쇄파나 모든 강비선형 현상이 자동으로 모델링되는 것은 아닙니다.

검토자 제안: 부유식 초기 평형, 질량·부력·계류력의 균형, 좌표 원점, 무게중심, 수력 계수 기준점을 먼저 점검하고, 이후 자유감쇠·규칙파·불규칙파로 복잡도를 높이는 방식이 원인 추적에 유리합니다. 이 번역 작업에서 이러한 수치 해석을 수행하지는 않았습니다.

InflowWind·TurbSim

InflowWind는 유입 풍장을 제공하며, 원문은 온라인 설명이 불완전하므로 기존 매뉴얼도 보라고 명시합니다. 사용자 정의 풍장은 WindType = 6의 구현 절차와 좌표계·오류 처리·성능을 자세히 다룹니다. 레지스트리의 데이터 구조 변경 후 타입 파일 재생성이 필요하다는 주의문을 놓치지 않아야 합니다.

TurbSim의 온라인 페이지는 원문 자체가 임시 항목이며 완성된 매뉴얼은 PDF 첨부로 제공됩니다. 따라서 웹 HTML 158개의 번역만으로 TurbSim PDF 전체의 한국어판까지 완성되는 것은 아닙니다. PDF와 예제 입력은 영어 원본 그대로 보존했습니다.

MoorDyn과 기타 모듈

MoorDyn 설명은 독립된 MoorDyn 문서로 연결되며 MoorDynF와 MoorDynC, V2 입력, FAST.Farm 수준 사용을 구분합니다. 외부 사이트 전체는 이번 main 문서 미러의 번역 범위에 포함되지 않습니다. IceDyn, IceFloe, FEAMooring, OrcaFlex 등도 추가 모듈 자료에서 별도 자료로 연결됩니다.

7. 제어·구조 제어·풍력단지·외부 연동

ServoDyn은 제어·전기 계통을 연결하며 확장 Bladed 인터페이스는 외부 제어기와 교환하는 채널·배열의 의미를 제공합니다. 제어기 DLL의 인터페이스, 입력 파일, 동작 주기와 신호의 단위를 함께 맞춰야 합니다.

구조 제어는 입력, 동조질량감쇠기 이론, TLCD 운동방정식과 참고문헌으로 구성됩니다. 질량·강성·감쇠·중력 방향·초기 위치의 정의를 같은 좌표계에서 읽어야 하며, 제어 장치의 응답이 전체 구조 모델의 감쇠 가정과 어떻게 결합되는지 확인할 필요가 있습니다.

FAST.Farm은 개별 터빈을 넘어 풍력단지의 후류와 상호작용을 다룹니다. 기호, 입력, 출력, 모델링 지침, 이론과 부록이 체계적입니다. 모델링 지침에서 저해상도·고해상도 풍장 영역과 시간·공간 해상도의 목적을 구분해야 합니다. 실행 지침에는 체크포인트 재시작이 아직 구현되지 않았다는 설명이 있습니다. 장시간 작업 계획에 영향을 주는 제약입니다.

C++ API는 외부 C++ 프로그램이나 CFD 솔버와 연결하는 경로입니다. 단순 실행 명령과 API 기반 연동은 입력·시간 진행·프로세스 관리의 책임이 다릅니다. WaveTank는 MHK 수조시험의 하드웨어 연동을 위한 실험적 코드라고 명시되어 있습니다. 일반 풍력터빈 시뮬레이터와 동일한 적용 범위로 보아서는 안 됩니다.

8. 선형화·후처리·검증

사용 절의 선형화 안내와 글루 코드의 선형화 설명을 함께 읽으면 운전점·상태·입력·출력·Jacobian 및 .lin 파일의 관계를 이해할 수 있습니다. 원문은 전체 비선형 시스템의 진동수가 운전 조건에 따라 달라지고, 모든 모듈·옵션이 선형화에 지원되지는 않는다고 명시합니다.

  • 운전점: 정상상태 수렴 여부와 선형화 시점을 확인합니다. 주기적 시스템에서는 방위각과 MBC 후처리를 함께 고려해야 합니다.
  • 출력 정밀도: 원문은 ASCII 선형화 출력의 OutFmt 정밀도가 고유치 해석에 영향을 줄 수 있다고 경고합니다.
  • 행렬 해석: A·B·C·D 행렬의 크기만 보는 대신 변수명, 단위, 미분 차수, 회전 좌표계 플래그와 선택된 입력·출력 집합을 대조해야 합니다.
  • 회귀 시험: 기준 결과와의 일치 여부를 평가합니다. 실험·현장 관측에 대한 검증, 난류 시드의 통계적 수렴, 설계하중조건의 충분성과는 다른 층위입니다.

9. 문서 품질 평가와 발견한 공백

장점: 사용자 입력에서 이론·출력·참고문헌으로 이어지는 구성이 강점입니다. SubDyn, BeamDyn, HydroDyn, OLAF, FAST.Farm은 수식과 구현·사용 정보를 함께 제공하며, 설치·테스트·개발 규약도 한 사이트에서 연결됩니다. 원문의 수식 번호·그림·표·내부 앵커를 유지한 이유도 이 참조 관계 때문입니다.

보완이 필요한 부분: 모듈마다 온라인화 수준이 다릅니다. TurbSim은 PDF 중심, InflowWind는 기존 매뉴얼 병행, MoorDyn은 외부 사이트 중심입니다. 일부 설명은 과거 버전 용어를 포함하고, HydroDyn의 참고자료에는 오래된 자료가 있을 수 있다고 원문이 직접 알립니다.

원문에서 확인된 깨진 경로: 개발자 API 관련 html/index.html, html/files.html, html/classes.html은 수집 시 HTTP 404였습니다. 없는 API 문서를 새로 만들어 원문 내용처럼 넣지 않았습니다. 해당 링크는 원문 주소를 유지하며 수집 기록에 남겼습니다. Python만으로 문서를 빌드하면 Doxygen API 설명이 생성되지 않는다는 원문 주의문도 참고할 수 있습니다.

  • 번역 범위: 같은 main 경로의 Sphinx 검색 색인 문서 158개와 검색·색인 보조 페이지입니다. 표시되는 설명·탐색 메뉴·제목·주요 접근성 속성을 번역했습니다.
